## 設計の核心（なぜこの形か）

Phase 1 で採用していた Supabase 標準のマジックリンク方式（`signInWithOtp({ shouldCreateUser: true })`）は、API 呼び出し時点で `auth.users` 行を作成する仕様だった。メール無視 / プロフィール入力で離脱したユーザーが auth.users / members に滞留する問題があり、これをサービスIN前に **Edge Function + 6 桁コード方式** で根本解決した（#189）。

**不変条件**: `auth.users` / `members` への INSERT は `verify-signup` Edge Function 成功時の唯一の経路に集約される。中途離脱者の痕跡は `signup_pending` テーブル（TTL 30 分）にしか残らない。

## 2. シーケンス図 - 新規会員登録ハッピーパス

```mermaid
sequenceDiagram
    participant User
    participant Browser
    participant ReqFn as request-signup
    participant VerFn as verify-signup
    participant Mailer as Gmail SMTP
    participant DB as Supabase DB
    participant Auth as Supabase Auth

    Note over User,Browser: 段階 1 signup フォーム入力
    User->>Browser: signup ページを開く
    User->>Browser: 全項目入力 + 同意 ON
    Browser->>Browser: Smart constructor バリデーション

    Note over Browser,Mailer: コード発行 auth.users members は作成されない
    Browser->>ReqFn: POST request-signup
    ReqFn->>ReqFn: サーバ側バリデーション再評価
    ReqFn->>DB: SELECT members WHERE email
    DB-->>ReqFn: 0 行 既登録チェック OK
    ReqFn->>DB: SELECT signup_pending WHERE email
    DB-->>ReqFn: created_at 60秒以内なら 429
    ReqFn->>ReqFn: 6桁コード生成 Web Crypto + SHA-256
    ReqFn->>DB: UPSERT signup_pending exp +30min
    DB-->>ReqFn: ok
    ReqFn->>Mailer: SMTPS send 件名 認証コード
    Mailer-->>User: 認証コードメール
    ReqFn-->>Browser: 200 ok true expiresAt
    Browser->>Browser: navigate signup verify

    Note over User,Auth: 段階 2 signup verify でコード検証
    User->>User: メール本文から 6桁取得
    User->>Browser: signup verify でコード入力
    Browser->>VerFn: POST verify-signup
    VerFn->>DB: SELECT signup_pending WHERE email
    DB-->>VerFn: payload + code_hash + expires_at
    VerFn->>VerFn: 期限チェック + ハッシュ照合 定数時間

    VerFn->>Auth: admin.createUser email_confirm true
    Auth->>DB: INSERT auth.users
    DB->>DB: trigger on_auth_user_created placeholder
    Auth-->>VerFn: user.id

    VerFn->>DB: UPSERT members 完成状態 placeholder 上書き
    DB-->>VerFn: ok

    VerFn->>DB: DELETE signup_pending WHERE email
    VerFn->>DB: DELETE signup_pending expires_at 1h超 ベストエフォート

    VerFn->>Auth: admin.generateLink type magiclink
    Auth-->>VerFn: hashed_token
    VerFn-->>Browser: 200 ok true tokenHash email

    Note over Browser,Auth: session 確立 + 次画面遷移
    Browser->>Auth: verifyOtp token_hash type magiclink
    Auth-->>Browser: 200 access_token refresh_token user
    Browser->>Browser: useAuthSession.refresh
    Browser->>DB: SELECT members WHERE id auth.uid
    DB-->>Browser: 完成プロフィール
    Browser->>DB: SELECT identity_documents
    DB-->>Browser: 0 行 未提出
    Browser->>User: navigate signup identity
```

## 4. シーケンス図 - 既存会員ログイン（マジックリンク方式は維持）

#189 で signup フローのみ Edge Function + 6 桁コード方式に置き換え、ログインは Phase 1 のマジックリンク方式を維持している。

```mermaid
sequenceDiagram
    participant User
    participant Browser
    participant Auth as Supabase Auth
    participant Mailer as Gmail SMTP
    participant DB as Supabase DB

    User->>Browser: login ページを開く
    User->>Browser: メールアドレス入力 + CTA
    Browser->>Auth: signInWithOtp shouldCreateUser false
    Auth->>DB: SELECT auth.users WHERE email
    alt 未登録メール
        Auth-->>Browser: error otp_disabled or user_not_found
        Browser->>User: 未登録です 新規会員登録へリンク表示
    else 既登録メール
        Auth->>Mailer: マジックリンクメール送信
        Mailer-->>User: ログインリンク email
        Auth-->>Browser: 200
        Browser->>Browser: navigate auth link-sent
    end

    User->>User: メール内リンククリック
    User->>Browser: auth callback で hash 受信
    Browser->>Auth: detectSessionInUrl 自動で hash 消化
    Auth-->>Browser: session 確立
    Browser->>Browser: useAuthSession.ready
    Browser->>DB: SELECT members WHERE id auth.uid
    DB-->>Browser: 完成プロフィール
    Browser->>User: navigate ホームまたは signup identity
```

## 主要な設計判断（design.md より要約）

| 判断 | 内容 | 出典 |
|---|---|---|
| Edge Function + 自前 6桁コード | Supabase 標準 OTP は auth.users 即作成のため不可。Edge Function 2 本で自前構築 | D1 |
| 1ページ全項目入力 | 2 段階だと中途離脱滞留が再発し要件矛盾 | D2 |
| signup_pending + 30分 TTL | コードハッシュ保管・期限切れ即削除・ベストエフォート掃除 | D3 |
| Gmail SMTP via nodemailer | denomailer の UTF-8 ヘッダー化けを回避。`npm:nodemailer@6.9.16` | D4 |
| ログインは現行据え置き | 中途滞留問題はログインで発生しないため変更最小化 | D5 |
| auth guard 簡素化 | プロフィール未完成分岐は到達不能のため削除 | D7 |

## Mermaid 構文上の注意

GitHub Mermaid プレビューは厳格なため、本ドキュメントの図は以下の原則で書かれている。編集時に違反するとパースエラーになる:

- ノードラベルは必ずダブルクォートで囲む（`Node["label"]`）
- スラッシュ `/` はラベル内でも避ける（Mermaid のシェイプ delimiter と衝突）
- subgraph タイトルは単純識別子のみ（クォート・括弧なし）
- classDef は使用しない（予約語衝突リスク）
- 多行ラベルは `<br/>` 区切り（`<br>` は不可）
- 半角括弧 `( )` / 半角コロン `:` は極力削除
