# 開発・コーディング規約

## アーキテクチャ：Feature Sliced Design（FSD）

> ADR: `docs/09-決定記録/ADR-0006-FSD採用.md`

FSD は **Layers → Slices → Segments** の3階層で構成される。
依存方向は **上位 → 下位の一方向のみ** 許可。逆方向・同一レイヤー間の直接 import は禁止。

```
app → pages → widgets → features → entities → shared
```

---

### レイヤー定義

#### `shared/` — 非ビジネスの汎用コード

ビジネスロジックを一切持たない。他のどのレイヤーからも import される基盤。

```
shared/
  ui/        ← 汎用UIコンポーネント（Button, Modal, Input など）
  api/       ← Supabase client, fetch wrapper, TanStack Query base config
  config/    ← 環境変数アクセス、定数（.env は直接触らない）
  lib/       ← 純粋ユーティリティ（日付フォーマット, バリデーションヘルパー）
  types/     ← 共通型定義（Result<T>, AppError, ErrorCode など）
  schemas/   ← Zod スキーマ（バリデーションルール）
```

**外部接続の境界**: Supabase client は `shared/api/` にのみ存在する。
`features/` や `entities/` が `supabaseClient` を直接 import することを禁止する。
必ず `shared/api/` の Public API 経由でアクセスすること。

```typescript
// ✅ Good — shared/api/ 経由
import { supabase } from '@shared/api';

// ❌ Bad — features から Supabase client を直接 import
// features/book-event/api/bookEvent.ts
import { createClient } from '@supabase/supabase-js'; // NG
```

テスト時の依存差し替えは `provide/inject` ではなく **MSW + TanStack Query の `queryClient`** で行う。

#### `entities/` — ビジネスエンティティの表現

「システムが何を知っているか」を表す。エンティティの表示・型・基本操作のみ。

本プロジェクトのエンティティ:

| エンティティ | 内容 |
|------------|------|
| `event` | イベント（開催日時・場所・定員） |
| `member` | 会員（氏名・連絡先・確認書類） |
| `reservation` | 予約（会員 × イベントの紐付け） |
| `session` | 認証セッション（ログイン状態） |

```
entities/
  event/
    ui/          ← EventCard.vue, EventBadge.vue
    model/       ← event.types.ts（Branded Types含む）, eventSchema.ts
    api/         ← TanStack Query options (queryOptions, mutationOptions)
    index.ts     ← Public API（外部に公開するものだけ export）
  member/
    ...
  reservation/
    ...
  session/
    ...
```

#### `features/` — ユーザーが「何をするか」

ユーザーインタラクション単位で切る。動詞で命名する。

本プロジェクトの主要フィーチャー:

| アプリ | フィーチャー | 説明 |
|--------|------------|------|
| LP | `view-event-calendar` | カレンダーでイベントを閲覧 |
| LP | `view-event-detail` | イベント詳細モーダルを開く |
| Admin | `create-event` | イベントを作成する |
| Admin | `edit-event` | イベントを編集する |
| Admin | `delete-event` | イベントを削除する |
| Admin | `manage-reservations` | 予約一覧を管理する |
| Admin | `verify-member` | 会員の本人確認 |
| Admin | `admin-auth` | 管理者ログイン |
| Reservation | `register-member` | 会員登録 |
| Reservation | `book-event` | イベントを予約する |
| Reservation | `cancel-reservation` | 予約をキャンセルする |
| Reservation | `member-auth` | 会員ログイン |
| Reservation | `view-my-reservations` | 自分の予約一覧を見る |

```
features/
  book-event/
    ui/          ← BookEventButton.vue, BookEventConfirmDialog.vue
    model/       ← useBookEvent.ts（composable）
    api/         ← bookEventMutation.ts（TanStack Query mutationOptions）
    index.ts
```

#### `widgets/` — 複数 features / entities を組み合わせた複合UIブロック

| ウィジェット | 内容 |
|------------|------|
| `event-calendar` | ナビ + カレンダー + イベントクリックモーダル（LP） |
| `admin-event-table` | イベント一覧テーブル + 操作ボタン群（Admin） |
| `reservation-form` | 予約フォーム全体 + 確認・完了ステップ（Reservation） |
| `member-id-upload` | 本人確認書類アップロード UI |

#### `pages/` — ルーティング単位のページ

**薄く保つ**。widgets の配置とページレイアウトのみ。ロジックを持たない。

#### `app/` — アプリ初期化

ルーター定義・プラグイン登録・グローバルスタイル。

### モノレポでの FSD 配置

```
apps/lp/src/          ← FSD（app + pages + widgets + features + entities + shared）
apps/admin/src/       ← FSD（同上）
apps/reservation/src/ ← FSD（同上）
packages/shared/src/  ← クロスアプリ shared（Supabase client・共通型・UIコンポーネント）
```

---

### Segments（スライス内の構造）

| セグメント | 内容 |
|-----------|------|
| `ui/` | Vue コンポーネント |
| `model/` | Composable・Pinia store・Branded Type 定義 |
| `api/` | TanStack Query の `queryOptions` / `mutationOptions` |
| `lib/` | このスライス専用のユーティリティ |
| `config/` | このスライス専用の定数・設定 |
| `index.ts` | **Public API**（外部に公開する唯一の出口） |

---

### Public API ルール（最重要）

**スライスの外から直接パスで import してはいけない。必ず `index.ts` 経由で import する。**

```typescript
// ✅ Good
import { EventCard } from '@entities/event';
import { useBookEvent } from '@features/book-event';

// ❌ Bad — 内部実装に直接依存
import { EventCard } from '@entities/event/ui/EventCard.vue';
import { useBookEvent } from '@features/book-event/model/useBookEvent';
```

`index.ts` に書いていないものは「外部非公開」とみなす。
この制約は **ESLint で自動検証する**（後述）。

---

### Cross-import ルール

同一レイヤーのスライス間は直接 import **禁止**。

```typescript
// ❌ Bad — features 内で別 feature を import
import { useBookEvent } from '@features/book-event'; // features → features NG

// ✅ Good — 共通ロジックは entities か shared に下ろす
import { useReservation } from '@entities/reservation';
```

## ESLint による FSD 境界の自動検証

**FSD のアーキテクチャルールは ESLint + dependency-cruiser + 静的検査 script で多層に自動検証し、Claude の「楽な import」を機械的に拒否する。**

実装は `.eslintrc.js`（legacy config）と `dependency-cruiser.config.js`。`apps/admin` / `apps/reservation` を対象とし、`apps/lp` は #310 (Vuetify 剥がし + TS 化) 完了まで対象外。

### 機械検知マトリクス

| 検知項目 | 第一層（IDE 即時） | 第二層（CI セーフティネット） | severity |
|---|---|---|---|
| FSD レイヤー方向 (app → pages → widgets → features → entities → shared) | `eslint-plugin-boundaries` の `element-types` | `dependency-cruiser` の `forbidden` rule | error |
| cross-slice import は Public API 経由 (深いパス禁止) | `boundaries/no-private` | - | error |
| Supabase client は `shared/api/` のみ | `@typescript-eslint/no-restricted-imports` (allowTypeImports: true) | - | error |
| `service_role` のクライアント露出 | `no-restricted-syntax` (Literal / TemplateElement) | `scripts/static-checks/grep-service-role.sh` | error |
| HQ デザイントークン経由（生 hex / 名前付きカラー禁止） | `stylelint` (`color-no-hex` / `color-named`) | - | warning |
| 循環依存 | - | `dependency-cruiser` (`no-circular`) | error |

### 例外設定

- **shared/api/** : `@typescript-eslint/no-restricted-imports` を off（Supabase client 直接利用が正しい場所）
- **shared/ui/** : `vue/no-reserved-component-names` を off（shadcn-vue primitives は HTML 予約名でコピーされる慣習）
- **spec / e2e** : `boundaries/*` と `no-restricted-syntax` を緩める（Mock / fixture 用）
- **supabase/functions/** : `service_role` 利用を許可
- **apps/lp/** : 上記すべての rule を off（#310 完了まで対象外）

### 既存例外の登録運用

migration の RLS / マイナンバー SOP 検査は新規 migration のみ強制し、既存は `scripts/static-checks/migrations-allowlist.txt` で除外する。**allowlist への追加は PR コメントで理由を明示**するルール。allowlist 追加が頻発する場合は rule 設計を見直す。

### ローカル / CI コマンド

```bash
# IDE と同等のローカル実行
pnpm -r lint                       # ESLint (全アプリ)
pnpm -r --if-present stylelint     # stylelint (admin / reservation)
pnpm depcruise                     # dependency-cruiser
pnpm static-checks                 # 全 bash 静的検査
```

CI では `lint` / `static-checks` / `migration-safety` (migration 変更時のみ) の各 job が並列に実行される。`.github/workflows/ci.yml` 参照。

## Value Object（Branded Types）

**プリミティブ型の多用を禁止し、ドメイン知識をカプセル化した型を `entities/<name>/model/` に定義する。**

Branded Types（型ブランディング）を使った軽量 Value Object パターンを採用する。クラスは使わない。

### Branded Type の定義

```typescript
// shared/types/brand.ts
declare const __brand: unique symbol;
export type Brand<T, B> = T & { readonly [__brand]: B };
```

### エンティティでの使用例

```typescript
// entities/event/model/event.types.ts
import type { Brand } from '@shared/types/brand';

// Branded Types — 生の string/number を直接渡せなくなる
export type EventId   = Brand<string, 'EventId'>;
export type Capacity  = Brand<number, 'Capacity'>;

// Smart constructor — バリデーションをここに集約
export function createEventId(value: string): EventId {
  if (!value.trim()) throw new AppError({ code: 'VALIDATION_FAILED', message: 'EventId は空にできません' });
  return value as EventId;
}

export function createCapacity(value: number): Capacity {
  if (!Number.isInteger(value) || value < 1 || value > 500) {
    throw new AppError({ code: 'VALIDATION_FAILED', message: '定員は1〜500の整数で指定してください' });
  }
  return value as Capacity;
}

// ドメインエンティティ — すべてのフィールドが readonly
export interface Event {
  readonly id:       EventId;
  readonly title:    string;
  readonly capacity: Capacity | null;
  readonly startAt:  Date;
  readonly endAt:    Date;
  readonly location: string;
}
```

```typescript
// 型の恩恵
const id: EventId = "abc-123";           // ❌ コンパイルエラー（型が違う）
const id: EventId = createEventId("abc-123"); // ✅
```

## エラー型（技術エラー + ドメインエラー）

技術的エラー（通信失敗等）とビジネス異常系（定員オーバー等）を明確に区別する。

```typescript
// shared/types/result.ts

// 技術的エラー（インフラ起因）
const TechnicalErrorCode = {
  NETWORK_ERROR:  'NETWORK_ERROR',  // 通信失敗
  SERVER_ERROR:   'SERVER_ERROR',   // 5xx
  NOT_FOUND:      'NOT_FOUND',      // 404
  UNAUTHORIZED:   'UNAUTHORIZED',   // 認証切れ
  FORBIDDEN:      'FORBIDDEN',      // 権限なし
  VALIDATION_FAILED: 'VALIDATION_FAILED', // 入力値不正
} as const;

// ビジネス異常系（ドメインルール起因）
const DomainErrorCode = {
  CAPACITY_EXCEEDED:      'CAPACITY_EXCEEDED',      // 定員オーバー
  DUPLICATE_RESERVATION:  'DUPLICATE_RESERVATION',  // 重複予約
  RESERVATION_CLOSED:     'RESERVATION_CLOSED',     // 受付終了
  MEMBER_NOT_VERIFIED:    'MEMBER_NOT_VERIFIED',    // 本人確認未完了
  PAST_EVENT:             'PAST_EVENT',             // 過去のイベント
  INSUFFICIENT_PERMISSIONS: 'INSUFFICIENT_PERMISSIONS', // 権限不足（ドメインルール）
} as const;

export const ErrorCode = { ...TechnicalErrorCode, ...DomainErrorCode } as const;
export type ErrorCode = keyof typeof ErrorCode;

export type AppError = {
  code: ErrorCode;
  message: string; // ユーザー向けメッセージ（日本語）
  cause?: unknown;
};

export type Result<T> =
  | { ok: true;  data: T }
  | { ok: false; error: AppError };
```

UI はエラーコードで表示内容を分岐し、「なぜ失敗したか」をユーザーに伝える。

```typescript
// ✅ Good — エラーコードでフィードバックを分岐
if (!result.ok) {
  switch (result.error.code) {
    case 'CAPACITY_EXCEEDED':
      showError('このイベントは定員に達しています');
      break;
    case 'DUPLICATE_RESERVATION':
      showError('すでにこのイベントに予約済みです');
      break;
    default:
      showError('予約に失敗しました。しばらくしてから再試行してください');
  }
}

// ❌ Bad — エラー内容をユーザーに伝えない
if (!result.ok) showError('エラーが発生しました');
```

## 状態管理の使い分け

| 用途 | 手段 |
|------|------|
| サーバーデータの取得・キャッシュ | **TanStack Query**（`@tanstack/vue-query`） |
| グローバル UI 状態（ログインユーザー・通知） | **Pinia** |
| 単一コンポーネントのローカル状態 | `ref` / `reactive` |
| 機能ロジック | **Composable**（`model/useXxx.ts`） |

```typescript
// entities/event/api/eventQueries.ts
import { queryOptions } from '@tanstack/vue-query';
import { supabase } from '@shared/api';           // shared/api 経由のみ
import type { Event } from '@entities/event';

export const eventQueryOptions = {
  list: () => queryOptions({
    queryKey: ['events'],
    queryFn:  async (): Promise<Event[]> => {
      const { data, error } = await supabase.from('events').select('*');
      if (error) throw new AppError({ code: 'SERVER_ERROR', message: 'イベントの取得に失敗しました' });
      return data;
    },
  }),
};
```

## TypeScript 規約

- `strict: true` を必ず有効化
- `noUncheckedIndexedAccess: true` を必ず有効化（配列・Record アクセスで `undefined` を強制）
- `any` 禁止。`unknown` + 型ガードで絞る
- 型アサーション（`as`）は Branded Type の Smart constructor 内のみ許可
- `catch` ブロックでのエラー握りつぶし禁止

### 型検査コマンド

各パッケージは `typecheck` スクリプトを公開する（仕様: `openspec/specs/typescript-baseline/spec.md`）。

```bash
# 個別パッケージの型検査
pnpm --filter @high-q/admin typecheck
pnpm --filter @high-q/reservation typecheck
pnpm --filter @high-q/shared typecheck

# モノレポ全体（ルートから）
pnpm -r typecheck
```

- `apps/admin` / `apps/reservation` は `vue-tsc --noEmit -p tsconfig.json`（Vue SFC を含む型検査）
- `packages/shared` は `tsc --noEmit -p tsconfig.json`
- `apps/lp` は段階移行中（Issue #130）。完了時点で自動的に `pnpm -r typecheck` の対象に加わる

## Vue 3 コーディング規約

- **`<script setup lang="ts">`** を使用（Options API は既存コード修正時のみ）
- `defineProps` / `defineEmits` は型引数スタイル
- `pages/` コンポーネントは薄く保つ（ロジックは `features/` / `widgets/` に下ろす）
