# ロギング方針

## 基本原則

1. **個人情報・認証情報をログに含めない**（絶対）
2. **本番環境では `console.log` を出力しない**（デバッグログはビルド時に除去）
3. **エラーは握りつぶさずログに記録する**
4. **構造化ロギング**を意識し、機械可読な形式を使う

---

## ログレベルの使い分け

| レベル | 用途 | 例 |
|--------|------|-----|
| `console.error` | ユーザー操作に影響するエラー | API失敗、認証エラー、バリデーション違反 |
| `console.warn` | 警告（動作は継続するが問題の可能性） | deprecatedなAPI使用、フォールバック発動 |
| `console.info` | 重要な状態変化 | ログイン成功、イベント予約完了 |
| `console.debug` | 開発時のみ（本番では無効化） | データフロー追跡、描画タイミング確認 |

## フロントエンドのログ方針

### 開発・本番の切り替え

```typescript
// src/utils/logger.ts
const isDev = import.meta.env.DEV;

export const logger = {
  error: (msg: string, context?: unknown) => console.error(`[ERROR] ${msg}`, context),
  warn:  (msg: string, context?: unknown) => { if (isDev) console.warn(`[WARN] ${msg}`, context); },
  info:  (msg: string, context?: unknown) => { if (isDev) console.info(`[INFO] ${msg}`, context); },
  debug: (msg: string, context?: unknown) => { if (isDev) console.debug(`[DEBUG] ${msg}`, context); },
};
```

### 必ずログに残す事象

- API リクエスト失敗（ステータスコード・エンドポイント、リクエストボディは含めない）
- 認証失敗（ユーザーIDのみ。パスワードは絶対に含めない）
- 想定外エラー（catch で握りつぶすことを禁止）
- 管理者による重要操作（イベント削除・ユーザー停止等）

```typescript
// ✅ Good
try {
  await supabase.from('events').delete().eq('id', eventId);
  logger.info('イベント削除', { eventId });
} catch (e) {
  logger.error('イベント削除失敗', { eventId, error: String(e) });
  throw new AppError('DELETE_FAILED', 'イベントの削除に失敗しました');
}

// ❌ Bad
try {
  await supabase.from('events').delete().eq('id', eventId);
} catch { /* 握りつぶし */ }
```

### ログに含めてはいけない情報

- パスワード・トークン・APIキー
- 氏名・電話番号・メールアドレス（フルテキスト）
- 本人確認書類の内容
- Supabase の service_role キー

## バックエンドのログ方針

### 既存 AWS 環境（LP）

- API Gateway / Lambda のログは CloudWatch に自動収集
- エラーは CloudWatch Logs Insights で `filter @message like "ERROR"` でフィルタ
- アラーム設定: エラー率 > 1% で通知（設定方法は `docs/03-アーキテクチャ/03-インフラ・CICD構成.md` 参照）

### 新規 Supabase 環境

- Supabase Dashboard → Logs → API Logs でリクエストログを確認
- PostgreSQL の `pg_audit` 拡張で DDL 操作（テーブル変更・削除）を記録
- Edge Function のログは Supabase Dashboard → Edge Functions → Logs

## テストにおけるログ

テスト実行中に `console.error` / `console.warn` が出力された場合はテスト失敗とみなす。
Vitest の設定でモック化し、意図しないエラーを検出する。

```typescript
// vitest.setup.ts
vi.spyOn(console, 'error').mockImplementation((msg) => {
  throw new Error(`Unexpected console.error: ${msg}`);
});
```
