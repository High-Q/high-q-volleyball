# 外部送信規律対応方針

## 目的

改正電気通信事業法 §27の12（外部送信規律、2023 年 6 月施行・罰則あり）への準拠。ユーザー情報を第三者に送信するサービスとして、(a) 送信される情報・送信先・利用目的の事前公表、および (b) 任意 cookie のオプトアウト手段提供を実装する。

関連 Issue: #192 / 関連 OpenSpec change: `external-transmission-compliance`

## 外部送信先一覧

| 送信先 | 区分 | 送信される情報 | 利用目的 |
|---|---|---|---|
| Google Tag Manager / Google Analytics | 任意 (analytics) | ページビュー、リファラ、ブラウザ識別情報、IP（推定地域算出用） | サイト利用状況の分析 |
| Google Fonts CDN | 必要 | フォントリクエスト時の IP / Referer / User-Agent | Web フォント配信 |
| Supabase（米国法人運営、データは日本リージョン保管）| 必要 | メール / 認証セッション / 会員情報 / 本人確認書類画像 | 認証・データ保管・ストレージ |
| Render（米国） | 必要 | アクセスログ（IP / User-Agent / リクエストパス） | Web ホスティング |
| AWS API Gateway / DynamoDB（LP 既存）| 必要 | アクセスログ（IP / User-Agent） | LP のイベント取得 API |

## Consent カテゴリ運用

- **`necessary`** — 拒否不可。Supabase Auth セッション等のサービス提供に不可欠な cookie 全般。法令上「公表」のみで足りる。
- **`analytics`** — 任意。GTM / GA 等の利用状況分析タグ。同意取得後にのみ動的ロード。

3 アプリ（lp / admin / reservation）で同意状態 schema を共通化（`packages/shared/src/consent/`）し、localStorage key `hq.consent.v1` で永続化する。各アプリの UI 自体は UI スタックの差異により個別実装。

## GTM consent gate 方式

- `apps/lp/index.html` の `<head>` に GTM の inline script を**直書きしてはならない**（過去の違反グレー解消）。
- `apps/lp/src/shared/lib/loadGtm.ts` が `analytics === true` 取得を契機に動的 script tag を `<head>` に挿入する。二重ロードガードあり。
- 同意前 / `analytics` 拒否のユーザーには `googletagmanager.com` への HTTP リクエストが**一切発生しない**（E2E で検証可能）。
- このため analytics 拒否ユーザー分の GA 計測は欠損する（法令準拠の必要コスト）。

## ポリシーページ配置

外部送信ポリシーページ `/external-transmission` は **LP に集約**（3 アプリ共通の単一 source of truth）。admin / reservation のフッターからは別オリジンへの外部リンク扱い（`target="_blank"` + `rel="noreferrer"`）で開く。

- LP 内: `apps/lp/src/pages/external-transmission/`
- admin / reservation 用 URL 解決: `apps/<app>/src/shared/lib/externalLinks.ts`（`VITE_LP_ORIGIN` で開発時は localhost 切替可）

## 更新時の確認ポイント

外部送信先（SaaS / CDN / 解析タグ）を新規追加する際は MUST:

1. 上記「外部送信先一覧」の表に行を追加
2. 区分（必要 / 任意）を判定。任意なら consent gate 化を検討
3. `apps/lp/src/pages/external-transmission/ui/ExternalTransmissionPage.vue` の `transmissions` 配列に追加
4. `transmissions` の最終更新日を更新
5. 必要に応じ各アプリの consent banner のテキストを更新
