# 個人情報保護方針 (内部運用版)

> 本文書は **内部運用 SOP** として、個人情報の取扱における具体的な運用手順・監査ポイントを定義する。
> 一般ユーザー向けの公開ポリシー本文は LP の `/privacy` ページ (`apps/lp/src/pages/privacy/`) を参照する。
> 両者は同一 PR で同時に更新する MUST。記載項目の網羅性は一致させ、表現粒度のみ調整する。

## 1. 適用範囲

本方針は High Q バレーボールサークルの以下サービスに適用される:

- ランディングページ (`apps/lp`)
- 管理画面 (`apps/admin`)
- 予約サイト (`apps/reservation`)

事業者: High Q バレーボールサークル / 連絡先: `high.q.volleyball@gmail.com`

## 2. 取得する個人情報の項目

| カテゴリ | 項目 | 保管場所 | センシティブ度 |
|---|---|---|---|
| 認証情報 | メールアドレス、マジックリンク認証セッション | Supabase Auth | 中 |
| プロフィール | 氏名、生年月日、電話番号、経験レベル | Supabase `members` テーブル | 中 |
| 本人確認書類画像 | 運転免許証等の顔写真付き身分証 / マスク済みマイナンバーカード | Supabase Storage (`identity-documents` バケット) | **極めて高** |
| 利用ログ | 予約・参加履歴 | Supabase `bookings` 等 | 低 |
| 利用ログ | アクセスログ (IP / User-Agent / リクエストパス) | Render プラットフォーム側 | 低 |

**マイナンバーカードの取扱**: 個人番号 12 桁は **完全マスクされた画像のみ受付**。テキストとしての保管は禁止 (`docs/06-品質・セキュリティ/08-本人確認書類取扱SOP.md` 準拠)。通知カードは一切受け付けない。

## 3. 利用目的 (個人情報保護法 §17)

1. 会員登録時の本人確認
2. イベント変更・中止等の連絡
3. 江東区・東京都へのスポーツ団体・社会教育団体登録の証憑提出
4. サービス提供 (予約管理・参加管理・出欠管理)
5. 障害発生時の調査・不正利用の調査・対応

利用目的の範囲を超えた取り扱いは行わない。利用目的を変更する場合は、変更前の目的と相当の関連性を有する範囲を超えないこと、または事前に本人の同意を取得することを徹底する。

## 4. 第三者提供 (個人情報保護法 §27)

以下の場合を除き、第三者へ提供しない:

1. 法令に基づく場合 (裁判所命令、警察照会等)
2. 江東区・東京都への団体登録の証憑として、admin が役所窓口へ書類を持参提出する場合

**業務委託先**:

| 委託先 | 役割 | 国・所在地 |
|---|---|---|
| Supabase | 認証・DB・Storage | 米国法人運営、データは可能な限り日本リージョン |
| Render | Web ホスティング・アクセスログ | 米国法人運営 |
| AWS (API Gateway / DynamoDB) | LP の既存イベント取得 API | 米国法人運営、東京リージョン |

委託先には個人情報保護法に基づく適切な監督を行う (契約上の守秘義務、セキュリティ要件の確認)。

## 5. 保管期間と退会後の処理

- **在籍中**: サービス提供のために必要な期間継続保管
- **退会時**: 本人確認書類画像を含む会員データを削除する。Supabase Storage オブジェクト・DB レコードの両方を対象とする
- **役所提出済の証憑コピー**: 法令上の保管期限が定められている場合は当該期限まで分離保管 (現状、団体登録証憑は 1 年単位で更新されるため翌年度までを目安とする)

## 6. 安全管理措置 (個人情報保護法 §23)

組織的・人的・物理的・技術的の 4 領域で安全管理措置を講じる。各領域の詳細運用は [docs/06-品質・セキュリティ/12-安全管理措置.md](./12-安全管理措置.md) に集約しており、本節はサマリのみとする (改定漏れ防止のため二重記載を避ける)。

### 6.1 組織的措置

個人情報取扱責任者をオーナー (翔太郎くん) と定め、ロールベース権限分離 (admin / member / 非会員) を DB / アプリ層の RLS で実装する。改訂履歴は Git で管理する。

### 6.2 人的措置

オーナー単独運営の前提で、業務外目的の個人情報閲覧禁止 / 第三者共有の制限 / AI ツール利用時の機密情報マスキング / 主要アカウントの 2FA 等を遵守する。

### 6.3 物理的措置

作業 PC のログインパスワード・スクリーンロック・ディスク暗号化を必須とする。個人情報を含む書類の物理印刷は原則禁止。端末紛失時は全 SaaS のセッション revoke を即時実施する。

### 6.4 技術的措置

Supabase RLS による行レベルアクセス制御、Storage の at-rest 暗号化、TLS 1.2 以上の通信暗号化、anon key のみの使用、マイナンバー 12 桁テキスト保管禁止、定期アクセス監査を実施する。

### 6.5 漏洩時対応

漏洩等が発生した場合は [docs/06-品質・セキュリティ/13-漏洩時対応SOP.md](./13-漏洩時対応SOP.md) に従い、検知 → 暫定対応 → 個人情報保護委員会への報告 (速報・確報) → 本人通知 → 再発防止策 の 5 ステップを遂行する。

## 7. 開示・訂正・利用停止等の請求対応 (個人情報保護法 §32-§35)

### 7.1 受付窓口

- 受付方法: メール (`high.q.volleyball@gmail.com`)
- 対応者: 翔太郎くん (オーナー兼開発者)

### 7.2 対応プロセス

1. 請求受領 → 受付確認返信 (3 営業日以内)
2. 本人確認 (登録メールアドレスからの請求であること確認 + 必要に応じて補助情報照会)
3. 開示・訂正・利用停止等の措置を実施 (合理的期間内、原則 2 週間以内)
4. 措置完了後、結果を本人に通知

### 7.3 不開示事由

以下に該当する場合は不開示とし、理由を本人に通知:

- 本人または第三者の生命・身体・財産その他の権利利益を害するおそれがある場合
- 業務の適正な実施に著しい支障を及ぼすおそれがある場合
- 他の法令に違反することとなる場合

### 7.4 手数料

開示・訂正・利用停止等の請求に係る手数料は、**MVP1 期間中は無料**とする。サービス規模拡大等により方針を変更する場合は、事前にプライバシーポリシーを改定し本人に通知する。

## 8. 外部送信規律 (改正電気通信事業法 §27の12) との関係

外部送信される情報の詳細 (送信先・送信される情報・利用目的・オプトアウト手段) は別途 `/external-transmission` ページに公表されている。Cookie 同意 UI は `packages/shared/src/consent/` で管理。

詳細: `docs/06-品質・セキュリティ/11-外部送信規律対応方針.md`
