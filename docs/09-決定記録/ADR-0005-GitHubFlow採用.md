# ADR-0005: GitHub Flow によるブランチ戦略の採用

- **日付**: 2026-04-24
- **状態**: 承認済み

## 背景

個人開発プロジェクトにおいてブランチ管理戦略を決定する必要がある。

## 決定

GitHub Flow を採用する。

- `main`: 本番（保護・PR必須・CI通過必須・直接 push 禁止）
- `feature/<issue番号>-<概要>`: 機能開発
- `fix/<issue番号>-<概要>`: バグ修正

## 理由

- 個人開発には Git Flow の `develop` / `release` ブランチは過剰
- シンプルな構造で運用コストが低い
- main へのマージ = デプロイ、という一貫したフローが維持できる
- CI/CD との統合がシンプル

## 却下した代替案

- **Git Flow**: `develop` / `release` / `hotfix` ブランチはチーム開発向けであり、個人開発には複雑すぎる
