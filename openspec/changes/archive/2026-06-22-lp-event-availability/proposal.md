## Why

LP（未ログインの誰でも見る集客ページ）のイベント一覧は、現在「日付・名前・時間・会場」しか出しておらず、空きがあるのか満員なのかが分からない。来訪者は予約サイトへ遷移して初めて埋まり具合を知るため、満員イベントへの無駄足や、「あと少しで埋まる」という予約の後押しの機会損失が生まれている。LP と予約サイトは既に同じ Supabase の events データを参照しているため、残席（定員と予約数の集計）を LP に出すことで、遷移前に判断材料を与えられる。

## What Changes

- LP のイベント一覧の各イベントに、予約サイトと統一した残席表現（「あと N 名 募集」／「満員」／無制限は「N 名 予約中」）を表示する。予約者の個人情報（個人名・誰が予約したか）は一切出さず、定員と予約数の集計値のみを用いる。
- 表現は予約サイトの残席規則に完全準拠し、LP 固有の分岐は設けない。無制限イベントの「N 名 予約中」は賑わいを示すソーシャルプルーフとして活かす。
- 満員イベントは「満員」を明示しつつ、予約サイトのキャンセル待ち登録へ誘導できるよう遷移は維持する。
- 残席の集計データを未認証ユーザー（anon）にも公開する。**BREAKING**: 既存仕様では「LP / anon は残席集計を参照してはならない」と定めていたため、この線引きを「個人情報を含まない集計に限り anon も参照可」に改訂する。集計の真実の源は二重化せず単一に保つ。
- 残席取得が失敗したイベントは、残席表現を伏せてイベント自体は通常どおり表示する（残席が出ないことで一覧全体が壊れない）。

### Modified Capabilities
- `lp-calendar`: LP のイベント表示に残席の表示要件を追加（募集中の残席数・満員・無制限・取得失敗の各状態）。
- `rls-policies`: 残席集計の参照を「LP / anon 禁止」から「個人情報を含まない集計に限り anon も可」に改訂する。

## Impact

- **LP（apps/lp）**: イベント取得経路に残席集計の取得を追加。イベント一覧コンポーネントに残席表現を追加。Loading / Empty / Error / Success の各状態に残席の表示・非表示を織り込む。
- **データアクセス（supabase）**: 残席集計を返す既存ビューの参照権限を anon に拡張する変更（権限のみ。集計ロジック・個人情報の露出範囲は変えない）。
- **表現の統一**: 予約サイトが既に持つ残席表現ロジックと文言・トーンを揃える（「席」表記は使わない等の既存ルールを踏襲）。
- **仕様**: `lp-calendar` と `rls-policies` の spec を更新。
