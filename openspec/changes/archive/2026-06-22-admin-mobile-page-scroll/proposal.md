## Why

スマホで admin の各画面を開くと、ページが画面の高さぴったりの「固定枠」に閉じ込められ、その枠の中で見出し・統計・タブ・検索ツールバーが上部を埋め尽くす。結果、本来見たい一覧（参加者一覧など）が画面下のごくわずかな領域に潰れ、数行しか見えず実質的に使えない。当日運営でスマホから参加者の確認やチェックインができない状態になっている。

原因は各ページが「画面の高さに固定した枠＋内側スクロール」というデスクトップ前提のレイアウトを、モバイルでもそのまま使っていること。共通レイアウトシェルはページ全体が自然に下スクロールする設計になっているのに、各ページがその上に固定枠を重ねて衝突している。

## What Changes

- **モバイル（< `md`）では、各ページのコンテンツを「固定枠＋内側スクロール」に閉じ込めず、ページ全体のスクロールに委ねる**。上部要素で押し下げられても、下方向にスクロールすれば一覧の全件に到達できるようにする。
- **デスクトップ（≥ `md`）は現行どおり**「ヘッダ固定＋本文だけ内側スクロール」を維持する（見た目・操作感を変えない）。
- 対象は同じ原因を抱える admin の主要画面: **イベント詳細（参加者一覧）/ イベント一覧 / 会員一覧 / 本人確認書類（一覧・詳細）/ 会場マスタ**。
- **配色・タイポ・部品・カードレイアウトは一切変えない**（スクロールの仕組みのみの修正）。一覧のカード縦積み化（`admin-mobile-responsive` で対応済み）はそのまま活かす。
- あわせて、参加者一覧の検索・フィルタ列がモバイルで中途半端に折り返して縦を浪費している点を、縦積みに整えて上部の高さ消費を抑える。

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `admin-responsive-shell`: 共通レスポンシブ表示規約に「モバイルでは各ページを画面高さ固定の内側スクロールに閉じ込めず、ページ全体のスクロールで全コンテンツに到達できるようにする（デスクトップは内側スクロールを維持してよい）」という挙動を追加する。

## Impact

- **影響コード**: `apps/admin` の対象 6 ページ（`pages/**`）と、参加者一覧の表示まわり widget（`widgets/event-detail`・`widgets/event-participants`）。スクロール／高さ指定の調整のみで、データ取得・状態管理・配色には触れない。
- **デスクトップ**: 挙動・見た目とも不変（変更はモバイル幅のみに効く）。リスクは低い。
- **アクセシビリティ / レスポンシブ**: 375 / 768 / 1280px で横スクロールを発生させない既存規約を維持する。
- **テスト**: モバイルビューポートで「イベント詳細を開き、下スクロールで参加者一覧の最後の行に到達できる」E2E を 1 本追加。スクロール構造の Component テストを必要分追加。
- **スコープ外**: ダッシュボード（固定枠パターンを使っていない）、ログイン / MFA 等の認証画面（`min-h-screen` 中央寄せで対象外）。
