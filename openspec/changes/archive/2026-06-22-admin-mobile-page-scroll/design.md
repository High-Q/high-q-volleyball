## Context

admin の各ページは「画面の高さに固定した枠（`h-screen`）＋本文だけ内側スクロール（`overflow-hidden` / `overflow-auto`）」というデスクトップ前提のレイアウトを採る。一方、共通レイアウトシェル `AdminShell` は最小高さ（`min-h-screen`）＋本文はスクロール指定なしで、**コンテンツが伸びたらページ全体が下スクロールする**設計になっている。

モバイルでは、シェル上部のアプリバー（ハンバーガー＋タイトル）の下に、各ページが画面高さぴったりの固定枠を重ねる。固定枠の中で見出し・統計カード・タブ・検索ツールバーが縦を食い尽くし、本来見たい一覧（参加者一覧など）の領域が画面下の数行分に潰れる。これが「参加者一覧が小さすぎて見えない」症状の構造的な原因。

一覧のカード縦積み化（`admin-mobile-responsive` で対応済み）は正しく機能しており、今回はその外側のスクロール構造だけを是正する。

対象ページ（同一パターン）:

| ページ | 種別 |
|---|---|
| `EventDetailPage`（参加者一覧）| 縦読み（見出し＋タブ＋一覧） |
| `EventsListPage` | 縦読み（一覧） |
| `MembersListPage` | 縦読み（一覧） |
| `IdentityDocumentsListPage` | 縦読み（一覧） |
| `IdentityDocumentDetailPage` | 縦読み（詳細） |
| `VenuesPage` / `VenuesMasterDetail` | マスター・ディテール（2ペイン）|

## Goals / Non-Goals

**Goals:**
- モバイル（< `md`）で、各ページのコンテンツをページ全体のスクロールに委ね、下スクロールで一覧の全件に到達できるようにする。
- デスクトップ（≥ `md`）の挙動・見た目を一切変えない（ヘッダ固定＋本文内側スクロールを維持）。
- 配色・タイポ・部品・カードレイアウトを変えない。スクロール構造のみの修正。

**Non-Goals:**
- デスクトップのレイアウト変更。
- 新しい色・spacing・コンポーネントの追加。
- ダッシュボード（固定枠パターン不使用）、ログイン / MFA 等の認証画面（`min-h-screen` 中央寄せで対象外）。
- 一覧のカード化やデータ取得・状態管理の変更。

## Decisions

### D1. ページ最外枠を `h-screen` → `min-h-screen md:h-screen` に変える

- **理由**: モバイルでは「最小で画面高さ・コンテンツが多ければ伸びる」挙動が欲しい。`min-h-screen` なら短いコンテンツでも画面を埋めつつ、長ければページが下に伸びてシェルのドキュメントスクロールに乗る。デスクトップは `md:h-screen`（後勝ち）で従来の固定枠を維持する。
- **代替案**: ①`h-screen` を完全削除 → デスクトップの固定枠が壊れ、内側スクロールの土台が消える。②モバイルで高さ指定なし（`h-auto`）→ コンテンツが短いとき画面下に余白が出て間延びする。`min-h-screen md:h-screen` が両立解。

### D2. 本文ラッパーの内側スクロールをモバイルで解除する

- ページ直下の本文ラッパー `flex-1 overflow-hidden` を `flex-1 md:overflow-hidden` に、内側のスクロール領域 `flex-1 overflow-auto` を `flex-1 md:overflow-auto` に変える（`md` 以上でのみ内側スクロール、モバイルは制約なしでコンテンツ分伸びる）。
- 参加者一覧では、本文ラッパー（`EventParticipantsWidget` のスクロール領域）と、その親タブパネル（`EventDetailWidget` の `flex-1 overflow-hidden`）の両方を同様に `md:` 化する。**入れ子の固定枠は途中の 1 段でも残ると潰れるため、最外枠からスクロール領域まで連鎖して解除する**。

### D3. 会場（マスター・ディテール）は同じ原則で、ペイン内スクロールを `md:` 化する

- `VenuesMasterDetail` は 2 ペインカード（`grid min-h-0 flex-1 overflow-hidden`）と各ペインの `overflow-y-auto` で内側スクロールする設計。これらの `min-h-0` / `overflow-hidden` / `overflow-y-auto` を `md:` プレフィックス化し、**デスクトップは 2 ペイン固定スクロールを維持、モバイルは list / form それぞれがコンテンツ高さでページスクロールに乗る**ようにする。
- フォームのフッターアクション（保存 / 削除）はモバイルでは画面下固定でなくなり、フォーム末尾にスクロールして到達する形になる。長文フォームを最後まで読んでから保存する自然な動線で、許容する。

### D4. 参加者一覧の検索・フィルタ列をモバイルで縦積みにする

- `EventParticipantsToolbar` は固定幅（検索＋経験＋状態フィルタ）が並び、モバイルで中途半端に折り返して縦を浪費している。モバイルでは各コントロールを全幅・縦積み、デスクトップは現行の横並びを維持する。上部の高さ消費を減らし、スクロール解除と相乗で一覧の見える量を増やす。

### D5. テスト戦略

- **E2E は追加しない**: admin の E2E は認証後フロー（AAL2 セッション再現）を意図的に E2E 化しておらず、認証後画面（イベント詳細・一覧など）の検証は component test に押し下げる既存方針（`e2e/admin/mobile-responsive.e2e.ts` 冒頭コメント参照）。本変更もこれに従い、認証が要る画面のスクロール到達を E2E では検証しない。
- **Component**: 参加者一覧ツールバー（`EventParticipantsToolbar`）のモバイル縦積み（root が縦積み・各コントロールが全幅、`md` 以上で横並び・固定幅）を検証する component test を追加する。既存のカード化テストは変更しない。
- **手動目視（主検証）**: 375 / 768 / 1280px で対象 6 ページ（＋参加者一覧・キャンセル待ちの両タブ）が、モバイルでページ全体スクロールにより全コンテンツへ到達でき、デスクトップで内側スクロールを維持し、いずれも横スクロールしないことを確認する。
- CLAUDE.md の運用に従い、UI 変更タスク連続のためテスト・ビルドは最終確認タスクで一括実行する。

## Risks / Trade-offs

- **[デスクトップ回帰]** `min-h-screen md:h-screen` の二重指定で意図せぬ高さになる → `md:h-screen` が後勝ちで適用され、デスクトップは現行どおり 100vh 固定。各ページのデスクトップ目視で確認。
- **[入れ子枠の見落とし]** 途中の 1 段でも `overflow-hidden` が残ると依然として潰れる → 参加者一覧（タブパネル → ウィジェット → スクロール領域）の連鎖を漏れなく `md:` 化する。grep で `overflow-hidden` / `overflow-auto` の残存を確認する。
- **[会場フッター非固定]** モバイルで保存ボタンが画面下固定でなくなる → フォーム末尾で到達でき、操作不能にはならない。必要なら別 Issue で sticky フッター化を検討（本変更スコープ外）。
- **[ロールバック]** 変更は Tailwind クラスへの `md:` 付与のみ。問題があれば該当コミットの revert で即時に現行へ戻せる。
