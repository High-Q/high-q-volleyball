## Context

`apps/admin` のイベント作成は `/events/new` の `EventForm`（`mode='create'`）で行う。フォーム項目はタイトル / 開催日 / 開始・終了時刻 / 会場 / 参加費の 6 つ。作成画面は `useVolumeSuggest` により「ゆる練 vol.NN」の次番号をタイトルのプレースホルダとして best-effort 提案する。一方、会場・時間・参加費は毎回ゼロ入力で、過去開催を下敷きにする導線がない。

イベント一覧 `/events` は `EventsTable` の操作列に「編集」リンク（`/events/:id/edit`）のみを持つ。行のタイトルは行全体を覆うストレッチリンク（`before:inset-0`）で詳細へ遷移し、編集リンクは `relative z-10` でその上に乗っている。

複製元イベントは `entities/event` の `getEventById` で取得でき、戻り値の `Event` には複製に必要な name / start_at / end_at / venue_id / fee が揃っている。`useEventForm` には既に `Event` をフォーム state へ変換する `eventToState`（JST 分解）が存在する。

## Goals / Non-Goals

**Goals:**
- 一覧の各行から 1 クリックで「その回を下敷きにした新規作成」を開始できる。
- 複製時に会場・時間・参加費・タイトルを引き継ぎ、開催日だけは空にして選び直させる。
- 連番形式のタイトルは複製時に次番号へ自動採番する。
- 複製は新規作成であり、複製元イベントには副作用を与えない。

**Non-Goals:**
- 一覧ヘッダの「過去から複製」ボタン＋ピッカーダイアログ（設計サンプルの形）は採用しない。
- 複製による一括作成・繰り返し予定（毎週など）の自動生成は対象外。
- CSV エクスポート / 一斉メール（Issue #153 の残り 2 機能）は後続 change で扱う。

## Decisions

### D1: 複製元の受け渡しは作成画面の URL クエリ `?from=<eventId>`

複製アクションは `/events/new?from=<eventId>` へ遷移する。理由:
- リロード・戻る/進む・URL 共有で複製コンテキストが保たれ、admin 全体の URL 同期方針と一致する。
- ルーター state やストアでの受け渡しは reload で失われ、テストもしづらい。

作成画面（`EventCreatePage`）が `from` を読み取り、`getEventById` で複製元を取得して `EventForm` に渡す。`from` が無い従来の `/events/new` は挙動を一切変えない（純粋な追加）。

**代替案**: 複製専用ルート `/events/duplicate/:id` を新設する案もあるが、作成画面そのものを再利用する方が DOM・バリデーション・送信経路を完全に共有でき、新規サーフェスが最小になるため不採用。

### D2: シード生成は純関数化し、`EventForm` の create mode に注入する

`Event`（複製元）→ フォーム初期 state への変換を純関数 `seedFromEvent(source, nextName)` として切り出す。挙動:
- 会場 / 開始時刻 / 終了時刻 / 参加費 → 複製元の値をそのまま引き継ぐ。
- 開催日 → 空文字（必ず選び直す）。
- タイトル → 連番採番の結果（D3）。

`EventCreatePage` が複製元と次タイトルを解決して `EventForm` に `seedEvent` を渡し、`useEventForm` は `initialEvent` 相当のシードとして create mode の初期 state に適用する。dirty 判定の基準スナップショットはシード適用後の state とする（シードしただけでは未保存促進のため dirty 扱いにはしない方針も検討するが、複製は「下敷きから編集して保存」が前提なので、開催日が空 = 未完成であることはバリデーションが担保する）。

### D3: 連番採番は複製元のタイトル番号ではなく全体の最大番号 +1

複製元が連番形式（語尾が `vol.<数字>`）の場合、`useVolumeSuggest` の `suggestNextVolume`（既存）を再利用し、events 全体の最大 vol +1 をタイトル初期値に入れる。複製元番号 +1 ではなく全体最大 +1 にする理由は、vol.42 を複製しても既に vol.45 が存在すれば vol.46 を提案し、番号衝突を避けられるため。連番形式でない複製元はタイトルをそのまま引き継ぐ（オーナーが編集する前提）。

`suggestNextVolume` が `undefined`（取得失敗 / 該当なし）を返した場合は複製元タイトルをそのまま用い、フォーム全体を Error にはしない（既存の縮退方針を踏襲）。

### D4: 操作列の「複製」リンクは既存ストレッチリンクと共存させる

`EventsTable` の操作列に「複製」リンクを「編集」の隣へ追加する。行タイトルのストレッチリンクの上に乗せるため `relative z-10` を付与し、`/events/new?from=<row.id>` へ遷移させる。色・余白は HQ デザイントークン（既存「編集」リンクと同じ utility）に揃え、リテラル色・spacing は使わない。a11y のため複製リンクには対象が分かる `aria-label`（例: 「<イベント名> を複製して新規作成」）を付与する。

### D5: 複製元取得の状態表示は作成画面内で完結させる

`?from` 指定時、`EventCreatePage` は複製元取得中は最小の Loading を出し、取得失敗（該当なし / RLS 不可 / 通信失敗）時は「複製元が見つかりません」の縮退として、複製シードなしの通常の空フォームにフォールバックして作成を続行できるようにする（複製は利便機能であり、失敗で作成自体を止めない）。取得成功時は「<複製元イベント名> を複製して作成中」の手がかりをフォーム上部に表示する。

## Risks / Trade-offs

- [複製元番号 +1 ではなく全体最大 +1 のため、オーナーの直感（「vol.42 を複製したから vol.43」）と一致しない場合がある] → 連番衝突を避ける方が運用事故が少ない。タイトルは編集可能なので、想定と違えばその場で直せる。手がかり表示で複製元名を示し混乱を抑える。
- [開催日を空にするため、複製直後に保存しようとするとバリデーションで止まる] → 仕様どおりの意図的挙動。日付欄を必須エラーで明示し、複製が「日付を変える操作」であることを体感させる。
- [`?from` に存在しない / 権限外の id を直接打たれる] → D5 のフォールバックで通常作成に縮退し、エラーにしない。複製元の閲覧可否は既存 RLS に委ね、新たな漏洩経路を作らない。
- [操作列にリンクが増え、行クリック（詳細遷移）と取り違える] → `relative z-10` と十分な間隔、`aria-label` で区別。既存「編集」と同じ構造のため新たな崩れは生じにくい。
