## Context

#193 で公開済みのプライバシーポリシー本文ページ (`apps/lp/src/pages/privacy/`) と基底 SOP (`docs/06-品質・セキュリティ/06-個人情報保護方針.md`) は、開示・訂正・利用停止等の請求窓口・対応プロセス・対応期日まではカバーしているが、**手数料の有無**だけが未記載のまま残っている。Issue #194 の完了条件 6 項のうち 5 項は既に充足済みで、本変更が最後の 1 項を満たし Issue クローズを可能にする。

LP は Vuetify 3 ベースで運用中（`apps/lp` の UI スタック方針）。本変更は静的文言の追記のみで、ロジック・データモデル・依存関係に変化はない。

## Goals / Non-Goals

**Goals:**
- 個情法上の請求権行使条件（手数料の有無）を本人が知り得る状態にする
- 公開ページ（プラポリ）と内部 SOP の双方で文言が整合する
- spec に手数料明示要件を固定し、将来のプラポリ改定で漏れない契約とする

**Non-Goals:**
- 手数料体系の設計（MVP1 では一律無料のため不要）
- 請求受付システムの構築（メール窓口の SOP 運用継続）
- プラポリ全体の改訂や法律家レビューの依頼（#193 のスコープに準拠）

## Decisions

### 決定 1: 手数料記載は MVP1 段階を限定で「無料」と明示する

無期限の「無料」コミットでなく、MVP1 期間中の方針として明示する。将来サービスが拡大した際に手数料を設定する余地を残す。文言例: 「本請求に係る手数料は、MVP1 期間中は無料です。」

**代替案**: 「無料」と無条件に記載 → 将来の見直しコストが発生し却下。

### 決定 2: 配置位置は既存「7. 開示・訂正・利用停止等の請求」セクション末尾

ページ・SOP ともに既存セクション 7 の末尾に「**手数料**」サブ項目として追記する。新セクション分割はしない（情報の凝集度を優先）。

### 決定 3: spec は MODIFIED Requirements で既存要件を上書き

`privacy-policy-page` の「請求窓口を明示する」要件に手数料サブ要件を追加する形で MODIFIED 扱い。新規要件として分離すると関連性が薄くなる。

### 決定 4: 影響レイヤー

- `pages` (LP `/privacy`): 本文 1 段落追記
- `docs` (SOP): §7 サブ項目追記
- `openspec/specs`: privacy-policy-page spec の MODIFIED delta（archive 時に統合）
- `widgets` / `features` / `entities` / `shared` / `app`: 影響なし

### 決定 5: UI 4 状態 / a11y / トークン使用

- **Loading / Empty / Error / Success**: 静的ページのため Success 状態のみ（既存ページと同等）。新規の loading・error 経路は発生しない
- **a11y**: 文言追記のみで、既存の見出し階層・ランドマーク構造に変更なし。AA 維持
- **デザイントークン**: 文言追記であり色・spacing 等の追加はないため、`var(--hq-*)` / Tailwind preset 利用判断は発生しない
- **モバイルファースト**: 既存ページのレイアウトを継承

### 決定 6: E2E ハッピーパス試験対象シナリオ

E2E は新規追加しない。**component test 1 件**のみ追加（`PrivacyPolicyPage.spec.js` 既存「開示請求セクションに 4 種請求権と mailto リンクが記載される」アサーションを拡張し「手数料」「無料」が描画されていることを確認）。CLAUDE.md の「機能あたり 1〜2 件まで」「詳細バリエーションは component test に押し下げる」方針に準拠。

## Risks / Trade-offs

- **Risk**: SOP とプラポリ本文で文言がドリフトする → **Mitigation**: tasks.md で SOP・プラポリ・spec の 3 箇所を 1 タスク内で連続更新し、PR 内で diff を相互確認
- **Risk**: 「MVP1 期間中は無料」の終期が曖昧 → **Mitigation**: SOP 改定履歴に記載し、Phase 移行時のリリース計画 (`docs/08-移行/01-環境戦略・本番リリース計画.md`) のチェックポイントに含める運用とする（本変更では運用記述のみ、リリース計画 doc 自体の改定は対象外）

## Migration Plan

不要（静的文言追記のためデプロイ即時反映、ロールバックは git revert）。
