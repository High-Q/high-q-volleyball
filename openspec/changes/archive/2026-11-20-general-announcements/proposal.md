# Proposal: 汎用お知らせ機能（general-announcements）

> **承認ゲート**: このドキュメントをレビューし、実装者と承認者が合意してから次フェーズへ進むこと。

## Why（なぜやるか）

オーナーが会員・来訪者へ伝えたい周知（例: 新規会員登録の一時停止、持ち物や会場の変更、休会のお知らせ）を出す手段が、今は何も無い。周知を 1 つ出すたびにコードを書き換えてデプロイするしかなく、オーナーが運営を離れる間（育児休暇等）は現実的に不可能になる。

#393（新規会員登録の受付停止トグル）では「公開 LP / 会員向けの周知は本機能で扱う」と明示的にスコープを切り出した。その委譲先が本機能であり、受付停止の周知を最初の 1 件として載せることを想定している。

オーナーが、コードに触れず・掲載期間を決めて・複数の周知を、公開サイト（LP）と会員向け予約サイトに出し入れできる、運用操作としての「お知らせ」基盤が必要。

## What Changes（何が変わるか）

| 観点 | 変更前 | 変更後 |
|------|--------|--------|
| 周知の掲載 | コード変更＋デプロイが必要 | admin から文章を書いて即時掲載 |
| 掲載期間 | 手動で消しに行く（消し忘れる） | 開始／終了を設定し自動で出し入れ |
| 複数の周知 | 不可（1 つ出すのも手作業） | 複数を同時に管理・掲載 |
| 出す相手 | 出し分け概念なし | 公開（LP）／会員（予約）／両方を選べる |
| 受付停止の周知（#393） | 周知手段なし | 本機能の 1 件として掲載 |

## Capabilities（実現できること）

- オーナーが admin でお知らせを**作成・編集・削除**でき、一覧で現在の掲載状態（掲載予定／掲載中／掲載終了）を把握できる。
- 各お知らせに**掲載期間**（開始・任意の終了）を設定でき、期間内のものだけが自動的に公開表示される。終了を空にすれば無期限掲載。
- お知らせの**出す相手**を選べる（公開サイト向け／会員向け／両方）。
- **公開サイト（LP）**の来訪者に、公開対象かつ掲載期間内のお知らせが表示される。
- **会員向け予約サイト**のログイン後トップに、会員対象かつ掲載期間内のお知らせが表示される。

## Impact（影響範囲）

### 影響するコンポーネント・ファイル

- **DB（Supabase）**: 複数行の `announcements` テーブルを新設（RLS つき・3 ロール明示 GRANT）。
- **admin アプリ**: お知らせ管理ページを新設（一覧＋作成／編集フォーム＋削除）。ナビゲーションに導線を追加。
- **LP アプリ**: 公開トップにお知らせ表示ブロックを追加（既存の Supabase + TanStack Query 基盤に乗せる）。
- **予約アプリ**: ログイン後トップ（`/events`）にお知らせ表示ブロックを追加（既存の composable データ取得流儀に合わせる）。

### 影響しない範囲（Non-Goals）

- 既存の `admin-announcement`（LINE / X 向け告知文コピー機能）とは**別物**。本機能はサイト内掲示であり、告知文テンプレートには一切触れない。
- 既存メンバーのログイン・予約・プロフィール・退会・本人確認など、お知らせ掲示以外の全機能。
- お知らせの**種別・重要度による装飾差**（色分け・アイコン）。MVP1 は単一の中立スタイルのみ。
- リッチテキスト・画像・リンクボタン・Markdown/HTML。MVP1 は改行を保持するプレーンテキストのみ。
- 個々の会員を狙い撃つ配信、既読管理、プッシュ通知・メール送信。掲示のみ。
- 予約開始通知や集客リマインド等の自動投稿（#288 / #289 の領域）。

## 制約・前提条件

- **掲載期間の判定は端末のタイムゾーンに依存せず、サーバー時刻（絶対時刻）で行う**。表示・入力の整形は日本時間（Asia/Tokyo）基準とする。
- 新規テーブルは `supabase/templates/new_table.sql` を出発点とし、RLS 有効化・anon / authenticated / service_role の 3 ロール明示 GRANT・`-- ROLLBACK:` コメントを含める（CLAUDE.md Pillar 4）。
- 公開読取の安全境界は **RLS で担保**する。anon には公開対象かつ掲載期間内の行だけ、会員には会員対象かつ掲載期間内の行だけを見せ、掲載前・掲載終了後の行は admin 以外に漏らさない。
- 既存のアプリ間でデータ取得流儀が異なる（LP = TanStack Query / admin・予約 = `Result` + 自前 composable）。各アプリは**自アプリの既存流儀に合わせて**実装し、新しい依存を持ち込まない。
- お知らせ本文はプレーンテキストとして扱い、HTML を解釈しない（XSS 防止）。

## 成功基準

- [ ] オーナーが admin でお知らせを作成・編集・削除でき、一覧で掲載状態を確認できる。
- [ ] 掲載期間の開始前は表示されず、期間内は表示され、終了後は自動的に消える（終了未設定は無期限掲載）。
- [ ] 出す相手の指定に従い、LP には公開対象、予約サイトには会員対象のお知らせだけが出る。
- [ ] 掲載前・掲載終了後のお知らせが anon / 一般会員に漏れない（RLS 検証 SQL で確認）。
- [ ] お知らせが 0 件・取得失敗のとき、LP / 予約サイトのレイアウトを壊さず静かにフォールバックする。
- [ ] 既存メンバー動線（ログイン・予約・退会）に回帰が無い。
