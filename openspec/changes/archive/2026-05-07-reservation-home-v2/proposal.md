## Why

会員サイトのログイン後ホーム (`/events`) は現状「開催予定イベントを並べた素朴な一覧」であり、ログイン直後に最も会員が知りたい情報 — **自分の次回予約はいつ・どこで・あと何日後か** — が一望できない。同じ画面内で「今からどう過ごすか (= 自分の次の予定)」と「これから探すか (= 他の開催予定)」が混在し、優先順位も曖昧になっている。

V2 では会員のホームを「自分の次回予約」を主役にしたヒーロー型レイアウトに刷新し、続いて他の開催予定をサブとして提示する構成に組み替える。これにより、リピート会員の体験 (Epic #170「メンバーが High Q に参加し、繰り返す」の "繰り返す" 部分) を強化する。

## What Changes

- **BREAKING**: 会員サイトのホーム画面 (`/events`) のレイアウトを、現行の「Upcoming kicker + 全件一覧」から「ヘッダ + NEXT カード + 他のイベントリスト」の 3 ブロック構成に置き換える
- ホーム最上部に **NEXT カード** (黒背景の大型ヒーロー) を新設し、ログイン会員の最早の予約済みイベント 1 件をカウントダウン・予約番号付きで表示する。タップで予約詳細画面 (`/reservations/:reservationId`) に遷移する
- 予約 0 件 (= NEXT カード対象なし) のときは NEXT カードを描画せず、上部の余白を詰めて他のイベントセクションを繰り上げる
- ホームの「他のイベント」セクションは upcoming events (NEXT に乗っているイベントを除く) を **全件** リスト表示する。デザインサンプル原案の「4 件 truncate + 「すべて ›」リンク」は MVP1 の開催頻度 (週 1 回・常時 ≤ 4 件想定) では過剰なため見送り、必要になった時点で別 Issue で再検討する
- ホームのヘッダにユーザー固有の **円形アバター** (右上配置・イニシャル表示) を追加し、押下でプロフィール画面 (`/profile`) へ遷移する。Bottom Tab Bar の「プロフィール」と機能的には併存する (iOS / Web 慣習に合わせた一次導線の重複)
- ホームの **パンくずを廃止** する (Bottom Tab Bar が一次ナビゲーションを担うため、ルート画面に対するパンくずは情報過多になる)
- 「他のイベント」行の **満員 / 初心者 / 残席数バッジは描画しない** (定員列・経験レベル区分は MVP1 スコープオフのためデータが存在しない)
- 予約詳細画面 (`/reservations/:id`) の Meta テーブルから **「経験レベル」行を撤廃** する。値の出どころは「会員自身の現在のプロフィール値」であり、予約のスナップショットでもイベント要件でもないため、自分の予約画面に再掲する必然性がない (プロフィール画面で編集できる自分の情報を別画面で繰り返すだけ)。Meta テーブルは「参加費 / 同伴者 / 予約日時」の 3 行構成に純化する

## Capabilities

### New Capabilities

なし。既存 capability `reservation-events-and-booking` の「ログイン後ホーム」要件を更新する形で吸収する。

### Modified Capabilities

- `reservation-events-and-booking`: ログイン後ホーム画面の構造を変更する。「イベント一覧画面」要件を「ホーム画面 (NEXT + 他のイベント)」要件に再構成し、パンくず要件からホーム画面を除外する。「他のイベント」リストは現行の一覧と同等の情報粒度 (日付・名前・時刻・参加費) を維持しつつ、上部に NEXT カードを伴う
- `reservation-detail-page`: 予約詳細画面の Meta テーブル要件から「経験レベル」行を撤廃する。`fetchMyReservation` の返却値からも会員の `experienceLevel` フィールドを削除する

## Impact

- **画面**: 会員サイト `/events` のレイアウトと情報設計が変わる。既存ブックマークは維持される (ルートは不変)
- **コード**: `apps/reservation` のホームページコンポーネント、新規 NEXT カードウィジェット、ホーム用ヘッダ (アバター)、自分の最早予約を取得する composable
- **データ**: 既存の `events` / `reservations` / `members` / `venues` テーブルのみ参照。スキーマ変更なし。RLS により他人の予約が NEXT カードに混入することはない (二重防衛として member_id 条件を明示)
- **テスト**: ホームの 4 状態 (Loading / Error / 予約あり / 予約なし) を component test で網羅する。E2E は #201 の予約フロー happy path に NEXT カード表示の検証を 1 件追加する余地を残す
- **デザイントークン**: 既存 `var(--hq-*)` と Tailwind preset utility のみで実装可能。新規トークンは追加しない
