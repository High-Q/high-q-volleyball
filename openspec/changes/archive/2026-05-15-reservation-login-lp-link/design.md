## Context

予約サイトのログインページ（`/login`）下部に「サークルについて詳しく ›」というラベルの導線がコード上には存在するが、`href="#"` のまま放置されており、コードコメントには「#90 周辺で正式配線」という暫定 TODO が残っている。一方、同じページ系統では既に「プライバシーポリシー」「外部送信ポリシー」が `shared/lib/externalLinks.ts` を経由して LP オリジン配下の URL に正規配線されている。LP 側は単一の `home` ページがサークル紹介を兼ねるランディング構成であり、現時点で「サークル紹介専用のサブパス」は存在しない。

ステークホルダー: ログイン前に「どんなサークルなのか」を確認したい見込み会員。フォーム入力途中で外部 LP に遷移する可能性があるため、入力状態を失わない遷移挙動が要点になる。

## Goals / Non-Goals

**Goals:**

- ログインページ下部のサークル紹介リンクを、確実に LP に着地する正規導線へ仕上げる
- 外部リンクヘルパー（`externalLinks.ts`）への責務集約を維持し、LP オリジン参照のばらつきを生まない
- ログインフォーム入力中に「うっかりサークル紹介を開いた」時に入力が消えないこと（新規タブ遷移）
- アクセシビリティ・セキュリティ上の外部リンク慣例（rel、target、aria）に従う

**Non-Goals:**

- LP 側の構造改修（about セクション専用 URL 化、アンカー追加、SEO 文言再構成）
- 同種リンクを他のページ（`/signup` 等）にも展開すること
- LP 既存 URL 構造の変更や、リダイレクト整備
- 新しい環境変数の追加（既存 `VITE_LP_ORIGIN` を再利用）

## Decisions

### 決定 1: 遷移先は LP のトップページに固定する

LP に「サークル紹介専用」の独立ページは存在せず、`home` がサークル紹介を兼ねたランディングである。ここに「about セクション専用 URL を LP 側に新設する」案も検討したが、本 change の動機（壊れた導線を埋める）に対しては過剰投資と判断。LP 側に約束した「サークル紹介」の置き場所を作り込む議論は、LP リニューアル側の Issue で扱う。

**採用**: LP オリジンのトップ（`/`）に遷移させ、ヘルパーに `LP_TOP_URL` という名前で export する。

**却下案**: LP に `/about` を新設してリンクする案。LP 側の改修コストと、LP リニューアル前にサブパスを増やすことのナビゲーション複雑化を考えると現時点では不利。

### 決定 2: 新しいタブで開く（`target="_blank"` + `rel="noopener noreferrer"`）

ログインページはフォーム入力中の画面でもある。同タブ遷移ではメールアドレス入力途中の状態が消える / 戻る動線で再入力が必要になるリスクがある。外部 LP は同一オリジン保証もない（環境変数で別ホスト指定可能）ため、`noopener noreferrer` を必ず付けてセキュリティ上の慣例に従う。

**採用**: `target="_blank"` + `rel="noopener noreferrer"`。`aria-label` で「新しいタブで開く」旨を伝える。

**却下案**: 同タブ遷移。フォーム入力途中で離脱すると再ログイン時の心理コストが上がるため不採用。

### 決定 3: URL 解決は既存 `externalLinks.ts` に集約する

`PRIVACY_POLICY_URL` / `EXTERNAL_TRANSMISSION_URL` と同じファイル・同じ `normalizedLpOrigin` 経由で `LP_TOP_URL` を export する。LoginPage 側で `import.meta.env` を直接読まないことで、テストでの差し替えと将来の LP オリジン移行が一箇所で済む。

**採用**: `shared/lib/externalLinks.ts` に `LP_TOP_URL` を追加 export。LoginPage は import するだけ。

**却下案**: LoginPage で直接 env を読む案。責務分散しテストもしづらく、既存ヘルパーの方針からの逸脱になる。

### 決定 4: spec への要件追加は ADDED で行う（既存要件の修正は最小化）

`reservation-member-auth` には会員登録 / マジックリンク / 4 状態 UI / プロフィール完成判定など 20 以上の Requirement が並んでおり、いずれも「ログイン画面のサークル紹介リンクの遷移先」は触れていない。既存 Requirement を MODIFIED にすると header 完全一致管理のリスクが膨らむため、新規 ADDED で「ログイン画面のサークル紹介外部リンク」を独立した Requirement として追加する。

**採用**: `## ADDED Requirements` セクションに 1 件追加。

## Risks / Trade-offs

- **[LP トップ URL がリブランド等で変わる]** → `externalLinks.ts` の 1 箇所修正で対応可能。`VITE_LP_ORIGIN` で本番 / Preview / dev の差は既に吸収済み
- **[ユーザーが新規タブ動作を嫌うことがある]** → 同タブにするとフォーム入力が失われるトレードオフがあり、「入力中の体験を守る」方を優先。UX 上の不満が顕在化したら別 Issue で再評価
- **[ヘルパー名 `LP_TOP_URL` と LP 構成の将来不整合]** → 将来 LP に `/about` を作って差し替えたい場合、定数名と export を 1 箇所書き換えれば追従可能。命名による拘束は弱い

## Migration Plan

- 既存 LP オリジン解決ロジック・既存リンクへの影響なし。LoginPage の差分のみで成立
- ロールバック手段: LoginPage の anchor を 1 行戻すだけで元に戻る（リスク極小）
- Render Preview で実際に「サークルについて詳しく」をクリックして LP に着地することを確認する

## Open Questions

- なし。LP トップ着地、`target="_blank"`、ヘルパー集約の 3 点で意思決定済み
