## Why

Issue #90 は Epic #170「メンバーが High Q に参加し、繰り返す」のユーザージャーニー **「探す」** にあたる体験を提供する。前段の会員登録・ログイン (#89) は完成したが、ログイン後のホーム画面は依然「準備中」のプレースホルダのままで、会員はイベントを見ることができない。

本 change は予約サイトの **イベント一覧** と **イベント詳細** の 2 画面を実装し、会員が「いつ・どこで・いくらで」開催されるかを把握できる状態を作る。次段の予約導線（予約確認・予約完了）は別 Issue (#91) として独立進行できるよう、本 change の境界を「詳細画面の『予約に進む』ボタンが描画されるところまで」に絞る。

### Issue #90 原案からの変更提案（PO 合意済）

Issue #90 の原案には「予約フォーム画面（氏名 / メール / 電話 / 同伴者数 / 連絡事項 / 規約同意の入力）」が含まれていたが、本 change では除外し後続 #91 のスコープに統合することを翔太郎くんと合意した。理由:

1. 氏名 / メール / 電話は会員登録時に正規化済であり、予約のたびに再入力させるのはユーザーに余計な手間を増やす
2. 同伴者人数 / 連絡事項 / 規約同意は確認画面に集約することで、「詳細 → 確認 → 完了」の 2 タップで予約が完結する体験になる

これにより本 change のスコープは「探す」体験のみに純化し、予約成立に関わる入力・確認・完了は #91 が一手に担う構造になる。

### MVP1 スコープオフ済み機能の事前確認結果

本 change の起票にあたり、関連する管理画面 spec を確認し、MVP1 でスコープオフ済みの機能項目を以下のとおり全件抽出した。これらに依存する UI 要素は本 change に **一切含めない**:

| スコープオフ項目 | 出典 | 会員サイトへの影響 |
|---|---|---|
| 定員入力 | `admin-events-crud` | 残席バー / 満員判定 / N/M 名 / キャンセル待ち UI を実装しない |
| 紹介文入力 | `admin-events-crud` | About / 紹介文セクションを実装しない（Markdown レンダリング・XSS 対策ライブラリも導入しない） |
| サムネイル画像 | `admin-events-crud` | ヒーロー画像領域 / 写真先行レイアウトを実装しない |
| キャンセル期限入力 | `admin-events-crud` | キャンセルポリシー欄を実装しない |
| 公開状態切替 UI | `admin-events-crud` | admin は常に公開状態で投入するため、会員サイトで「下書き」表示は発生しない（フィルタは安全策として残す） |
| 中止 / 終了ステータス切替 | `admin-events-list` | admin に切替 UI がないため、全イベントが開催予定状態。会員サイトで中止表示の必要なし |

この結果、会員サイトが扱う情報は **イベント名 / 開催日時 / 会場 (名 + 住所) / 参加費** の 4 項目に純化される。

## What Changes

| 観点 | 変更前 | 変更後 |
|------|--------|--------|
| 会員ログイン後のホーム | 「準備中」プレースホルダ画面 | イベント一覧画面 |
| 開催予定イベントの可視性 | 会員は確認できない | 開催日順に閲覧可能 |
| イベント詳細の閲覧 | 不可 | イベント名・開催日時・会場（名 + 住所）・参加費を確認できる |
| 予約への入口 | 存在しない | 詳細画面に「予約に進む」ボタンを設置（接続先の確認・完了画面は #91 で実装） |

## Capabilities

### New Capabilities

- `reservation-events-and-booking`: 会員サイトの「探す」体験。開催予定イベントの一覧表示、開催日順の並び、ミニマル詳細画面（イベント名・開催日時・会場名・会場住所・参加費）、4 状態 UI（読み込み中・該当なし・エラー・正常表示）、戻り経路を担保するパンくずナビゲーション、詳細から予約導線への入口ボタンの配置までを担う。**実際の予約成立処理（同伴者人数の入力・規約同意・確定操作・完了通知）は本 change のスコープ外**で、後続 Issue #91 が引き取る

### Modified Capabilities

- `app-routing`: 会員サイトの会員ログイン後のホーム遷移先を「準備中」プレースホルダからイベント一覧へ切り替える。新たに「イベント一覧」「イベント詳細」の 2 ルートを追加する

## Impact

### 影響するコンポーネント・ファイル

- 会員サイト (`apps/reservation`) のページ・ウィジェット・ルーティング配下に、イベント一覧・詳細の画面群および関連コンポーネントを新規追加
- ログイン直後の遷移先設定を「準備中」からイベント一覧に変更
- 既存の「準備中」プレースホルダページは削除
- DB スキーマ変更なし
- RLS 変更なし（既存ポリシーで成立）
- 新規パッケージ依存追加なし

### 影響しない範囲（Non-Goals）

**後続 Issue へ押し出す項目:**

- 予約フォーム / 予約確認画面 / 予約完了画面（**Issue #91**）
- 同伴者人数の入力 UI / 連絡事項 / 規約同意（**#91**）
- 予約の DB 確定処理（**#91**）
- 予約完了メール通知（**#91 以降**）
- ニックネーム表示への切替（**Issue #200**。本 change は氏名前提で実装し、#200 で表示文言を一斉切替する想定）
- プロフィール編集（**Issue #148**）

**MVP1 全体スコープアウト（管理画面 spec で確認済）:**

- 定員入力 / 残席バー / 満員判定 / キャンセル待ち UI
- イベント紹介文（About セクション・Markdown レンダリング）
- イベント写真（ヒーロー画像・写真先行レイアウト）
- キャンセル期限・キャンセルポリシー欄
- 下書き / 限定公開 / 中止 / 終了 のステータス表示

**MVP2 押し下げ:**

- 通知設定 / 統計
- イベント詳細 Variation B（テキスト先行）と 3 ステップ進捗バー化
