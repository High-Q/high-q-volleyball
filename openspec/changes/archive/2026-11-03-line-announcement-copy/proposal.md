# Proposal: LINE / X 告知文のワンタップ作成と予約への直行

> **承認ゲート**: このドキュメントをレビューし、実装者と承認者が合意してから次フェーズへ進むこと。
> 関連 Issue: #386「LINE 告知文のワンタップ作成（テンプレート編集）と予約への直行リンク」（Epic #170）

## Why（なぜやるか）

LINE オープンチャットの告知まわりに、会員側とオーナー側の両方で手間がかかっている。

**会員側: 告知から予約までの手順が多い**。告知リンクが予約サイトの**イベント一覧**を指しているため、会員は次の手順を踏む:

1. 告知のリンクをタップ → **LINE アプリ内ブラウザ**で開く
2. ログイン画面 → メール入力 → メールアプリでログインリンクをタップ
3. ログインリンクは **Safari / Chrome（標準ブラウザ）** で開く → イベント一覧
4. 一覧から該当イベントを探してタップ → 詳細 → 「予約する」→ 予約シート → 確定

原因は 2 つ。(a) ログイン状態は標準ブラウザに保存されるのに、告知リンクは LINE アプリ内ブラウザで開くため、LINE から開くたびに未ログインに戻る。(b) 告知が一覧を指している。イベント個別ページへの直リンクと「予約シートを自動で開く」仕組み、「ログイン後に元のページへ戻る」仕組みは既に実装済みだが、告知では使われていない。

**オーナー側: 告知文を毎回手で組み立てている**。日時・会場・参加費・予約 URL を手で書き換えており、手間と書き間違いのもとになっている（`announcements/` 配下の下書き）。

**X でも告知したい**。X で届くのは High Q を知らない人なので、オープンチャット向けとは違う「私も参加していいんだ」と思える文面と、いきなりログイン画面ではなくサークル紹介（LP）へのリンクが向いている。

## What Changes（何が変わるか）

| 観点 | 変更前 | 変更後 |
|------|--------|--------|
| 告知文の作成 | 毎回手書き・手で書き換え | admin のイベント詳細「告知文をコピー」で、テンプレートにイベント情報を差し込んだ文面をワンタップでコピー |
| 告知文の定型部分 | 下書きファイルを手で管理 | admin の「告知テンプレート」画面で編集・保存（LINE 用・X 用の 2 つ） |
| X の告知 | （していない） | 知らない人向けの X 用テンプレート（初期値は紹介ページへのリンク・X の文字数表示つき）からコピー |
| リンクの種類 | 一覧 URL のみ | 予約直行リンクと紹介ページ（LP）リンクの 2 種類。テンプレートでどちらか・両方を選べる |
| 告知に貼るリンク | イベント一覧 | そのイベントの予約画面へ直行するリンク（予約シートが自動で開き、標準ブラウザで開く） |
| LINE から開いたときのブラウザ | LINE アプリ内ブラウザ（未ログイン） | 標準ブラウザ（前回ログインのまま） |
| ログイン済み会員の手順 | 上記 1〜4（ログイン + 一覧選択） | リンクをタップ → 予約シートで確定（**2 タップ**） |
| 未ログイン会員の手順 | ログイン後に一覧から選び直し | ログイン後、そのイベントの予約シートが開いた状態で戻る |
| 予約済みの会員がリンクを開いたとき | （今後の問題）新規予約シートが開き、確定すると重複エラー | 予約シートは開かず、自分の予約状態が表示される |

## 実現できること

- admin はイベント詳細で LINE / X を切り替えて告知文のプレビューを確認し、ワンタップでコピーできる。
- admin は「告知テンプレート」画面で、定型文と差し込み項目（日付・時刻・会場・参加費・予約リンク・紹介ページリンクなど）を組み合わせた LINE 用・X 用テンプレートを編集できる。X 用は X の文字数（上限 280）を確認できる。
- 会員は告知リンクをタップすると標準ブラウザで開き、ログイン済みならそのまま予約シートで確定できる。
- 未ログインの会員・新規の参加希望者も、ログイン / 会員登録を終えると目的イベントの予約シートに戻ってくる。

## Capabilities

### New Capabilities

- `admin-announcement`: 告知チャネル（LINE / X）、告知テンプレートの編集画面、差し込み項目の展開規則、X の文字数カウント、イベント詳細からの告知文 / リンクのコピー。

### Modified Capabilities

- `admin-event-detail`: ヘッダのアクションに「告知文をコピー」を追加する。
- `admin-responsive-shell`: グローバルナビに「告知テンプレート」を追加する。
- `reservation-booking-flow`: 予約シートを自動で開くリンクを告知からの入口としても位置づけ、予約済み会員には開かない条件と LINE 用パラメータの扱いを定める。
- `data-schema`: 告知テンプレートを保存するテーブルを追加する。

## Impact（影響範囲）

### 影響するコンポーネント・ファイル

- DB: 告知テンプレート用テーブルの新設（migration・RLS・初期テンプレート投入）
- admin: 告知テンプレート画面（新設）、ナビ項目追加、イベント詳細のヘッダ + 告知文ダイアログ、予約サイト URL の設定（新設）
- reservation: イベント詳細の自動オープン判定とクエリ処理
- Edge Function / 環境変数の追加: **なし**

### 影響しない範囲（Non-Goals）

- **同じチャネル内でのテンプレート複数管理**（ゆる練用・通常練習用などの使い分け）・ジモティー用: 今回は LINE 用・X 用の各 1 つ。保存の仕組みはチャネルを後から増やせる形にしておく。
- **LINE / X への自動投稿・共有画面（投稿画面）の起動**: 投稿は admin がコピーして手で貼る。共有画面の起動やイベント作成直後の自動表示は #288「イベント作成時に LINE オープンチャットへ予約開始通知を自動投稿」の change に残す（同 change は本 change の後に、告知文生成部分を除いて縮小する）。
- **イベント詳細をログイン無しで見られるようにすること**: 公開範囲（RLS）の見直しが必要なため別検討。
- **ログイン方式の変更**（6 桁コード入力でアプリ内ブラウザのまま完結など）: 今回の外部ブラウザ誘導の効果を見てから判断。

## 制約・前提条件

- 標準ブラウザで開かせる仕組みは LINE 公式のリンクパラメータ（`openExternalBrowser=1`）に依存する。オープンチャット上での動作は Apply 中に実機（iPhone / Android）で確認する。
- **残るリスク（iPhone）**: Safari は 7 日間（Safari を使った日数で数える）サイトを開かないとログイン状態を消すことがある。開催が月 1〜2 回だと、iPhone 会員は時々ログインし直しになる可能性がある。その場合もログイン後は予約シートに直行する。
- 告知リンクは常に本番の予約サイトを指す（開発時のみ環境変数で差し替え可能）。
- migration を含むため、マージ後の本番 DB 反映は CI の承認ゲート（prd-db-push）経由になる。承認まで見届けてから完了とする。

## 成功基準

- [ ] admin の告知テンプレート画面で LINE 用・X 用テンプレートを編集・保存できる
- [ ] admin のイベント詳細で、イベント情報が差し込まれた告知文をコピーして LINE / X に貼れる
- [ ] ログイン済み会員が LINE の告知リンクをタップすると、標準ブラウザで予約シートが開いた状態になる
- [ ] 未ログイン会員がリンクから開いた場合、ログイン後に同じイベントの予約シートが開く
- [ ] 予約済み・受付終了・満席のイベントでは予約シートは開かない
