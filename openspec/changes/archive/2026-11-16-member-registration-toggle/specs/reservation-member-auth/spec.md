## ADDED Requirements

### Requirement: 新規登録受付停止ゲート（サーバー側）

受付が停止中のとき、新規会員登録のサーバー側処理は会員を作らず拒否する MUST。判定は認証コード発行（`request-signup`）と会員作成（`verify-signup`）の**両方**の入口で行う SHALL。停止中は専用エラー（`registration-suspended`, HTTP 503）を返す SHALL。受付可否の読取に失敗した場合は「停止中」とみなして拒否する（フェイルクローズ）MUST。本ゲートは新規登録フローのみに作用し、既存メンバーのログイン・予約・退会・本人確認等の処理には一切作用しない MUST。

#### Scenario: 停止中はコード発行が拒否される
- **WHEN** 受付停止中に `request-signup` が呼ばれる
- **THEN** 認証コードは発行・送信されず、`registration-suspended`（503）が返る

#### Scenario: 停止中は会員作成が拒否される
- **WHEN** 受付停止中に `verify-signup` が（進行中コードで）呼ばれる
- **THEN** `auth.users` / `members` は作成されず、`registration-suspended`（503）が返る

#### Scenario: 受付可否の読取失敗はフェイルクローズ
- **WHEN** 受付可否フラグの読取がエラーになった状態で `request-signup` / `verify-signup` が呼ばれる
- **THEN** 停止中として扱い新規会員は作られない。読取失敗は error monitoring に記録される

#### Scenario: 受付中は従来どおり登録できる
- **WHEN** 受付中（既定状態）で新規登録フローを実行する
- **THEN** コード発行・会員作成とも従来どおり成功する

#### Scenario: 停止は既存メンバー機能に波及しない
- **WHEN** 受付停止中に既存メンバーがログイン・予約・退会などを行う
- **THEN** いずれも通常どおり動作する（停止ゲートの影響を受けない）

### Requirement: `/signup` 受付停止中の表示

`/signup`（会員登録入口）は、受付停止中はフォームの代わりに「受付停止中」の案内を表示する SHALL。案内は停止の旨と `/login` への導線を含む MUST。受付可否の読取に失敗した場合はフォームを表示する（フェイルオープン）SHALL。ただし送信時のサーバー側ゲートが権威判定であり、UI が開いて見えても停止中は会員が作られないことは保証される MUST。

#### Scenario: 停止中はフォームの代わりに案内を表示
- **WHEN** 受付停止中に `/signup` へアクセスする
- **THEN** 入力フォームは表示されず、受付停止中の案内と `/login` への導線が表示される

#### Scenario: 受付中は従来どおりフォームを表示
- **WHEN** 受付中に `/signup` へアクセスする
- **THEN** 従来どおり会員登録フォームが表示される

#### Scenario: 読取失敗時はフォームを表示（フェイルオープン）
- **WHEN** 受付可否の読取に失敗した状態で `/signup` へアクセスする
- **THEN** フォームが表示される（誤って門前払いしない）。停止中であれば送信時にサーバー側ゲートが拒否する

### Requirement: `/signup/verify` の停止時挙動

受付停止中に進行中の認証コードで `/signup/verify` から会員作成を試みた場合、ページはサーバー側ゲートの拒否（503）を受けて受付停止中の案内に切り替える SHALL。会員は作られない MUST。

#### Scenario: 進行中コードでの検証が停止中に拒否される
- **WHEN** 受付停止中に `/signup/verify` でコードを送信する
- **THEN** サーバー側ゲートが 503 で拒否し、ページは受付停止中の案内を表示する。会員は作られない
