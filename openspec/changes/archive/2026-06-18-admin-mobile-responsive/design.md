## Context

`apps/admin` はデスクトップ前提で構築されており、グローバルナビ（ダッシュボード / イベント / 会員 / 会場 / 本人確認書類 / ログアウト）が各ページの上部 header に重複実装されている。共通レイアウトシェルは存在せず（`App.vue` は `RouterView` + Footer のみ）、データ一覧は `shared/ui` の Table を横スクロールで提示している。スマホ幅では header のリンク行・テーブル・多カラムが破綻する。

デザインプロトタイプ（`docs/10-デザインサンプル/admin/`、視覚的な正）には 240px の左サイドバー（`SidebarNav`）と per-page `TopBar` が存在するが、実装には降りていない。本変更でこのシェルを実装に導入し、全画面をレスポンシブに折り畳む。新しいモバイル専用 UI（下部タブナビ・当日モード画面）は作らない。

制約: FSD 厳守 / Public API 経由 / Supabase client は `shared/api` のみ / HQ デザイントークン経由のみ（生 hex 禁止）/ 既存の見た目・情報量を回帰させない。

## Goals / Non-Goals

**Goals:**
- デスクトップ＝左固定サイドバー、モバイル（< `md`）＝アプリバー + ドロワーの共通レイアウトシェルを `widgets/admin-shell` として導入する。
- 散在するグローバルナビをシェル 1 箇所へ集約し、各ページ header はパンくず + タイトル + ページ固有アクションのみに縮約する。
- 全データテーブルをモバイルでカード縦積みに切り替える（横スクロールを廃止、全項目保持、重要状態は色で表現）。
- 統計グリッド / 本文 2 カラム / フォームのラベル列・入力列・行内グリッドをモバイルで縦積みにする。
- 375 / 768 / 1280px で対象全画面が横スクロールなしで破綻しない。

**Non-Goals:**
- 設定（`/settings`）画面・独立 404/403 エラーページの新設（未実装ゆえスコープ外）。
- 下部タブナビ・当日チェックイン専用画面の新設（Issue #155 本文からのピボット）。チェックインタブの disabled 解除も本変更では行わない。
- 配色・タイポ・コンポーネント意匠の変更、新色の追加。
- 機能・データ取得ロジックの変更（レイアウトのみ）。

## Decisions

### D1: シェルは `widgets/admin-shell`、認証配下ルートのみ適用
`App.vue` がルート種別に応じてシェルの有無を切り替える。認証配下ルート（ダッシュボード / イベント / 会員 / 会場 / 本人確認書類）はシェルで包む。**公開ルート（login / mfa / mfa-setup / auth-callback）はシェル無し**でレンダリングする（ログイン前にナビを出さない）。

- デスクトップ（≥ `md`）: 240px の `<aside>` サイドバー（ブランド + ナビ + ユーザー/ログアウト）。
- モバイル（< `md`）: 上部アプリバー（ハンバーガー + 画面タイトル + 主要アクション 1 つ）＋ ドロワー。

> 代替案: 各ページが自前でサイドバーを描画 → 重複と不整合のため却下。シェル集約が FSD 的にも正。

### D2: ナビ集約 — ページは TopBar、主要アクションは Teleport でアプリバーへ
グローバルナビ（会員 / 本人確認書類 + pending Badge / ログアウト / 各セクションリンク）をシェルへ移設する。各ページ header（`TopBar`）はパンくず + タイトル + **ページ固有の主要アクション**（例: ダッシュボード/イベント一覧の「新しいイベントを作る」、CRUD の「保存」「削除」）のみを担う。

- 画面タイトルは `route.meta.title` から取得し、デスクトップは `TopBar`、モバイルはアプリバーに表示。
- モバイルのアプリバー右の「主要アクション 1 つ」は **Teleport ターゲット**をアプリバーに置き、各ページが自身の主要アクションをそこへ Teleport する。デスクトップでは `TopBar` 内に通常描画。

> 代替案: アクションを `route.meta` に静的定義 → 動的（保存可否で disabled 等）に弱いため Teleport を採用。

### D3: テーブル→カードは「デスクトップ Table / モバイル カードリスト」の出し分け
共通の超汎用 `ResponsiveTable`（列定義駆動）は作らない。カード内容（イベント / 会員 / 参加者 / 会場 / 本人確認書類）はバッジ・色・項目が各エンティティで異なり、設定駆動は過抽象になるため。

- `shared/ui` に軽量 `DataCardList`（モバイル時コンテナ `md:hidden` + 余白 + リストの a11y セマンティクス）を追加。
- 各一覧 widget は **デスクトップ用 Table（`hidden md:…`）とモバイル用カード（`DataCardList` + 各 widget 固有のカードテンプレート）を併置**する。横スクロールは使わない。PC の全列をカード内に「ラベル: 値」で保持し、重要状態（チェックイン済 等）は背景色で表現。

> 代替案: 列定義 1 本から table/card を自動生成 → カードのバッジ/配色差異で破綻するため却下。

### D4: ブレークポイントは Tailwind デフォルト `md` = 768px
モバイル / デスクトップの境界は `md`（768px）。中間調整（3 カラム→2 カラム等）は `lg`（1024px）。カスタム screens は追加しない（既存 preset のデフォルトを使用）。幅依存で再利用される少数の箇所のみ、必要なら CSS コンテナクエリを個別検討。

### D5: ドロワーは shadcn-vue `Sheet` を新規取得（a11y はプリミティブに委譲）
ドロワーのフォーカストラップ / Esc / スクリム / スクロールロック / `aria-modal` を自前実装せず、shadcn-vue の `Sheet`（reka-ui ベース）を `apps/admin/src/shared/ui/` に copy-paste で取り込む（CLAUDE.md「機能系 = shadcn-vue・追加は必要時に個別取得」に準拠）。ハンバーガーに `aria-expanded`、クローズ時にハンバーガーへフォーカス返却。

> 代替案: 自前ドロワー + 手書きフォーカストラップ → a11y バグ温床のため却下。

### D6: 会場（master-detail）はモバイルでビュー切替
`/venues` はデスクトップで「左リスト + 右フォーム」。モバイルでは横並びが収まらないため、**リスト表示 → 会場選択でフォームビューへ切替**（同一ルート内のビュー状態切替、戻る導線あり）。デスクトップの master-detail は不変。

### D7: ログイン/認証ページはシェル外で個別レスポンシブ
ログインはデスクトップ「左ブランド帯 + 右フォーム」、モバイルは縦積み（ブランドを上部の細い帯へ圧縮、装飾コピー非表示、フォーム全幅）。MFA / auth-callback は中央寄せの単純フォームのため軽微調整のみ。

### D8: サイドバーのナビ項目は実在ルートのみ
ナビ項目 = ダッシュボード（`/`）/ イベント（`/events`）/ 会員（`/members`）/ 会場（`/venues`）/ 本人確認書類（`/identity-documents`、pending Badge）。**設定はルート未実装のため出さない**。フッターにユーザー表示 + ログアウト。

## Risks / Trade-offs

- **[全画面のナビ構造が変わる BREAKING・PR 肥大]** → Apply は「シェル新設 → 一覧/テーブル系 → フォーム系 → 詳細/会場 → ログイン/エラー」の順で 1 タスク 1 コミット。各幅（375/768/1280）でデスクトップ視覚回帰が無いことを各段で確認。PR が過大なら「シェル + ナビ移設」と「画面別レスポンシブ」で 2 PR 分割も可（Open Questions 参照）。
- **[テーブル→カードのエンティティ別重複]** → `DataCardList` で枠を共通化し、カード本体のみ各 widget で実装。切替の Component テストで担保。
- **[ナビ移設で双方向対称導線の既存要件（venues spec）を壊す恐れ]** → シェルが全画面で対称ナビを提供することで充足。`admin-venues-crud` / `admin-dashboard` の該当要件を本変更で更新。
- **[既存 spec が「モバイル=横スクロール」を SHALL 化している]**（events-list / event-detail / members-list / identity-documents）→ 当該要件を「カード縦積み」へ MODIFIED で反転。header 文字列は完全一致でコピーしてから編集。
- **[E2E モバイルの不安定さ]** → モバイルビューポートの happy path 1 本に限定（ログイン → イベント詳細 → 参加者チェックイン）。詳細は Component テスト。

## Migration Plan

1. `widgets/admin-shell`（サイドバー + アプリバー + ドロワー）と `shared/ui` の `Sheet` / `DataCardList` を追加（TDD: ドロワー開閉・キーボード・カード切替）。
2. `App.vue` を認証配下ルートでシェル経由描画に変更。各ページから重複グローバルナビを削除し `TopBar` へ縮約、主要アクションを Teleport 化。
3. 一覧系（events / members / venues / identity-documents）をテーブル→カード対応へ。
4. フォーム系（events-crud / venues フォーム）の縦積み確認・調整。
5. ログイン/MFA/エラーのレスポンシブ調整。
6. モバイル E2E 1 本 + 最終確認（`pnpm exec vitest run` / lint / typecheck / build）。

ロールバック: シェル導入はレイアウト層のみで DB/API に触れないため、PR revert で原状復帰可能。

## Open Questions

- 1 PR で出すか、「シェル + ナビ移設」と「画面別レスポンシブ」の 2 PR に分割するか（規模次第。デフォルトは 1 PR・段階コミット、レビュー負荷が高ければ分割）。
- アプリバーのモバイル主要アクションを持たない画面（会員一覧等）でのアプリバー右側の扱い（空 or 検索アイコン等）— 実装時に各画面で確定。
