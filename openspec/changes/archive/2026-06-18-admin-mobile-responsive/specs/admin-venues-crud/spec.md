## MODIFIED Requirements

### Requirement: 会場画面への遷移とアクセス制御

システムは `/venues` を admin auth guard 配下に配置 MUST する。未認証・非 admin ユーザーは既存 guard により会場画面へ到達しない SHALL。会場を含む各セクション（ダッシュボード / イベント / 会員 / 本人確認書類 / 会場）への双方向対称の導線は、`admin-responsive-shell` capability のサイドバー / ドロワーが MUST 提供する。会場画面は自前のグローバルナビ行を持たず、ページ header はパンくず + タイトルのみに縮約する SHALL。

#### Scenario: 非 admin は会場画面に到達しない
- **WHEN** 非 admin ユーザーが `/venues` にアクセスする
- **THEN** 既存の admin auth guard によりログイン等へリダイレクトされ、会場画面は表示されない

#### Scenario: シェルから会場画面へ
- **WHEN** admin がシェルのナビ（サイドバー or ドロワー）の「会場」を押す
- **THEN** `/venues` へ遷移し、同じシェルのナビから他セクションへ戻れる

## ADDED Requirements

### Requirement: 会場マスター・ディテールのモバイル表示

`/venues` の「左リスト + 右フォーム」master-detail は、デスクトップ（≥ `md`）で横並びを維持する。**モバイル（< `md`）では MUST 横並びをやめ、会場リスト表示と詳細フォーム表示をビュー切替で出し分ける**（リストで会場を選択するとフォームビューへ遷移し、フォームからリストへ戻れる導線を持つ）。詳細フォームは MUST 1 カラムで縦積みになり、行内グリッド（メイン会場フラグ等を含む各項目）も縦積みになる。横スクロールは発生させない。

#### Scenario: モバイルでビュー切替になる
- **WHEN** 画面幅 375px で `/venues` を開く
- **THEN** 左右横並びではなく会場リストが表示され、会場を選択すると詳細フォームビューへ切り替わり、フォームからリストへ戻れる

#### Scenario: モバイルでフォームが 1 カラム縦積みになる
- **WHEN** 画面幅 375px で会場の詳細フォームを表示する
- **THEN** フォーム項目が 1 カラムで縦積みに配置され、横スクロールは発生しない
