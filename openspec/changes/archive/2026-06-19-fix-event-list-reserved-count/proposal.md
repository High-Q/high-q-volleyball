## Why

admin の `/events` 一覧画面の残席表示が、実際の予約人数とずれている。一覧で使う集計値だけが「予約件数（同伴者を数えない）」かつ「チェックイン前のみ」を数える独自ロジックになっており、詳細画面・会員向け画面が共有する「本人＋同伴の人数」「チェックイン後も減らない」という正しい集計と食い違っているため。結果として残席が実際より多く見え、チェックインを進めると一覧の数字が不自然に減る二重の表示バグが起きている。

## What Changes

- 一覧画面の残席集計を、詳細画面・会員向け画面と完全に同じ「本人＋同伴者の合計人数・予約中＋チェックイン済みを母集団とする」定義に統一する
- これにより、同伴者を含めた残席が一覧でも正しく表示され、チェックイン操作で一覧の数字が減る不具合も解消する
- 定員未設定イベントの一覧表示が「件数」を意味する単位になっているのを、人数ベースに合わせた単位へ揃える

## Capabilities

### New Capabilities

（なし。既存の不具合修正のため新規 capability は発生しない）

### Modified Capabilities

- `data-schema`: 一覧用ビューの残席集計値の定義を、詳細・会員向けビューと同一の「本人＋同伴の人数・予約中＋チェックイン済み」に変更する（要件本文と集計シナリオの MODIFIED）

## Impact

- admin 一覧画面の残席表示のみ。詳細画面・会員向け画面・予約フローの挙動は変わらない
- DB: 一覧用ビューの再定義（migration 1 本）。テーブル・RLS・権限・型契約の列構成は不変
- UI: 一覧テーブルの単位表記の微修正と関連テストの期待値更新のみ。残席バーや型定義の構造変更はなし
