## Why

`apps/admin` はデスクトップ前提で実装されており、各画面のグローバルナビは「各ページが自前で持つ上部 header のリンク行」に散在している。スマホ幅では header のリンク行・データテーブル・多カラムレイアウトが破綻し、当日運営（受付・チェックイン）をはじめ管理操作をスマホから完結できない。

本変更は **新しいモバイル専用 UI を作らず、既存の管理画面を同じ部品・同じ見た目のままレスポンシブに折り畳む**。あわせて、デザインプロトタイプ（視覚的な正）にあるが実装に降りていない **共通レイアウトシェル（デスクトップ＝左サイドバー / モバイル＝アプリバー + ドロワー）** を導入し、散在するグローバルナビを 1 箇所へ集約する。

## What Changes

- **共通レイアウトシェルを新設**する。デスクトップは左固定サイドバー（ブランド + グローバルナビ + ユーザー/ログアウト）、モバイルはアプリバー（ハンバーガー + 画面タイトル + 主要アクション 1 つ）＋ドロワー（左スライド + スクリム、Esc / スクリム外タップ / フォーカストラップ / スクロールロック）。
- **各ページのグローバルナビをシェルへ移設**する。ページ側 header はパンくず + タイトル + ページ固有アクションのみを担う。**BREAKING**（admin 全画面のナビ構造が変わる。デスクトップの見た目はサイドバー導入分だけ変化）。
- **データテーブルをモバイルでカード縦積みに切り替える**共通の表示パターンを導入する。横スクロールは使わず、PC で見える全項目をカード内に保持する（重要状態は色で表現）。
- **多カラム（統計グリッド / 本文 2 カラム / フォームのラベル列・入力列・行内グリッド）をモバイルで縦積み**にする。
- **当日チェックインの操作要素のタップ領域を 44px 以上**に確保する（チェックインタブそのものの開通は本変更のスコープ外＝Issue #155 本文との差分。後述 Impact 参照）。
- 対象は実在する全画面: ログイン / MFA、ダッシュボード、イベント一覧、イベント作成・編集、イベント詳細・参加者、メンバー一覧、会場マスタ、本人確認書類（一覧・詳細）、エラー（既存分のみ）。
- 配色・タイポ・コンポーネントの見た目は変えない（HQ デザイントークン経由のみ）。重要データを隠さない。

## Capabilities

### New Capabilities
- `admin-responsive-shell`: admin 全画面を包む共通レイアウトシェルの責務。デスクトップ左サイドバー / モバイルアプリバー + ドロワー、グローバルナビの集約、レスポンシブ規約（基準ブレークポイント・44px タップ領域・テーブル→カード変換の共通表示パターン・多カラム→縦積み）、ドロワーのアクセシビリティ（フォーカストラップ / Esc / スクリム / スクロールロック / `aria-expanded`）を定義する。

### Modified Capabilities
- `admin-dashboard`: グローバルナビ行をシェルへ移設。統計カードグリッドと本文 2 カラムのモバイル縦積みを要件化。
- `admin-events-list`: グローバルナビ移設。モバイルでのテーブル表示を「横スクロール」から「カード縦積み（全項目保持）」へ変更。
- `admin-event-detail`: グローバルナビ移設。サマリカードのモバイル段組、タブの横スクロール、参加者テーブルのカード化（チェックイン状態を色で表現・各バッジ保持）。
- `admin-members-list`: グローバルナビ移設。メンバーテーブルのモバイルカード化。
- `admin-venues-crud`: グローバルナビ移設。会場テーブルのモバイルカード化、フォームのモバイル縦積み。
- `admin-identity-document-review`: グローバルナビ移設。一覧テーブルのモバイルカード化。
- `admin-auth`: ログイン画面の「左ブランド帯 + 右フォーム」をモバイルで縦積みにする要件を追加。

> `admin-events-crud` は既にモバイルファースト要件を持ち、ページ header にグローバルナビを持たないため spec 要件の変更は不要（シェル配下に置く実装変更のみ。delta なし）。

## Impact

- **影響コード**: `apps/admin` 全 `pages/**` と関連 `widgets/**`。新規 `widgets/admin-shell`（シェル）と、テーブル→カード変換の共通表示コンポーネント（`widgets` または `shared/ui`）。`App.vue` がシェルを介して `RouterView` を描画する構成へ。
- **FSD / 機械検知**: レイヤー境界（`eslint-plugin-boundaries`）・Public API 経由・`dependency-cruiser`・`stylelint`（生 hex 禁止）をすべて満たす。新色は作らない。
- **アクセシビリティ**: ドロワーのフォーカストラップ / Esc / スクロールロック、44px タップ領域、`aria-expanded`。
- **テスト**: シェル（ドロワー開閉・キーボード操作）とテーブル→カード切替の Component テストを TDD で追加。モバイルビューポートで「ログイン → イベント詳細 → 参加者チェックイン」の E2E を 1 本。
- **スコープ外（明示）**:
  - **設定（`/settings`）画面はルート・実装ともに存在しない** → 本変更で新設しない（必要なら別 Issue）。
  - **独立した 404/403 エラー画面（catch-all）は未実装** → 既存のエラー表示のみレスポンシブ確認。新規エラーページは作らない。
  - **Issue #155 本文が要求する「下部タブナビ」「当日チェックイン専用画面」は作らない**（レスポンシブ折り畳み方針へのピボット）。チェックインタブの disabled 解除・専用画面は別途。ship 時に Issue #155 本文を本方針に合わせて更新する。
