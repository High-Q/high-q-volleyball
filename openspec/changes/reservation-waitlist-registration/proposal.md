## Why

満員イベントに対して会員が「空きが出たら参加したい」意思を表明する手段が、予約サイトのどこにも存在しない。現状は満員時に「予約に進む」CTA を「予約締切」で無効化するだけで、待機する導線が無い。このため admin 側のキャンセル待ち管理 (#154) が参照する `reservations.status = 'waitlist'` の行を生み出す経路が一つも無く、当該機能が常に空のまま成立しない。本 change はその唯一の入口（会員からのキャンセル待ち登録）を提供する。

加えて、現状の `reservations` INSERT ポリシーは挿入時の `status` を一切制限していないため、会員が自分の行に対して `'attended'` 等の管理者専用ステータスを直接 INSERT して参加実績を偽装し得る潜在的な整合性ホールが存在する。キャンセル待ち登録という「会員が設定してよいステータスの拡張」を導入する本 change は、この境界を明文化して塞ぐ適切なタイミングでもある。

## What Changes

- 満員イベント詳細の下部 CTA を、当該会員が未登録のとき「予約締切（無効）」から「キャンセル待ちに登録」（押下可能）へ切り替える。既にキャンセル待ち登録済みの会員には「キャンセル待ち登録済み」状態を表示し、二重登録を抑止する。
- キャンセル待ち登録は既存の予約確認 Bottom Sheet を **waitlist モード**として再利用する。同伴者数のスナップショットは取得するが、参加費の合計金額提示は行わず（この段階では支払い確約ではないため）、文言とアクションをキャンセル待ち向けに差し替える。
- 登録の確定で当該会員の `reservations.status = 'waitlist'` 行を作成する。過去に同一イベントをキャンセル済みの行が残っている場合は、その行をキャンセル待ちへ再活性化する。
- イベント詳細画面が、当該会員自身の当該イベントに対する予約状態を取得するようになり、CTA の分岐（未登録 / 予約済み / キャンセル待ち登録済み）を駆動する。
- 登録完了は画面内のフィードバック（トースト + 状態表示）で完結させる。登録完了メールは送らない。「枠が空きました」という価値の高い通知は admin 側の繰り上げフロー (#154) の責務とし、本 change では扱わない。
- **BREAKING**（RLS 契約）: `reservations` の INSERT / UPDATE ポリシーを、会員が自分の行に対して設定してよいステータス集合（キャンセル待ちを含む）に明示的に限定する。これにより会員による管理者専用ステータスの自己設定を遮断しつつ、キャンセル待ち登録と再活性化を許可する。

## Capabilities

### New Capabilities

- `reservation-waitlist-registration`: 満員イベントに対する会員からのキャンセル待ち登録の振る舞いを規定する。CTA 分岐（未登録 / 予約済み / 登録済み）、予約確認 Bottom Sheet のシェルを再利用したキャンセル待ち登録 UI、waitlist 行の作成と再活性化、二重登録の防止、登録後フィードバック、当該会員の自己予約状態取得、4 状態 UI とテストカバレッジを含む。

### Modified Capabilities

- `reservation-events-and-booking`: 満員時のイベント詳細 CTA の要件を、無条件に無効化された「予約締切」から、当該会員が未登録のときキャンセル待ち登録導線を提示する形へ変更する（具体的な登録の振る舞いは新 capability `reservation-waitlist-registration` が規定）。
- `rls-policies`: `reservations` の INSERT / UPDATE ポリシーを、会員が自己の行に設定可能なステータス集合をキャンセル待ちまで含めて明示限定する形へ変更する。

> キャンセル待ち登録 UI は予約確認 Bottom Sheet（`reservation-booking-flow` capability）のシェルを再利用するが、キャンセル待ちは「予約」（支払い確約）とは別概念のため、`reservation-booking-flow` の create / edit 2 モード兼用要件自体は変更しない。シェル再利用と waitlist 用の表示差分は新 capability 側で規定する。

## Impact

- 影響コード: `apps/reservation` のイベント詳細ページ・予約 Bottom Sheet・予約 entity / booking API・イベント詳細 composable。
- DB / セキュリティ: `reservations` の RLS ポリシー migration（INSERT / UPDATE の WITH CHECK 句変更）。テーブル列・スキーマ自体の変更は無し。
- 連携: admin キャンセル待ち管理 (#154) が消費する `waitlist` 行の生成元となる。予約履歴画面のキャンセル待ちバッジ表示は既存仕様（`reservation-history-page`）のまま。
- 通知: メール送信フロー（Edge Function）には手を入れない。
