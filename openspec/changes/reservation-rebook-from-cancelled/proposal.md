## Why

予約をキャンセルした会員が「気が変わってやっぱり参加したい」と思っても、現状はキャンセル済予約とイベントの紐付きが UI 上で失われ、イベント一覧から目的のイベントを再度たどり直す必要がある。再活性化（cancelled → reserved）の書き込みロジックは既に成立しているのに、そこへ至る導線だけが欠けており、低摩擦の再参加機会を取りこぼしている。

## What Changes

- 履歴画面 (`/history`) に「キャンセル済み」セクションを新設し、キャンセル済予約を過去グループから分離して集約する。受付可能な行には「再予約する」導線を置き、受付終了・満席の行には導線を出さない。
- 予約完了画面 (`booking-done`) でのキャンセル直後、対象イベントがまだ受付可能なときに限り「やっぱり予約する」導線を提示する（イベント一覧へ飛ばして再予約導線を失う現挙動を、受付可能時のみ置き換える）。
- 上記 2 経路を、イベント詳細を起点に予約 Sheet（create モード）を直接立ち上げる共通の導線に集約する。受付終了・満席のイベントには導線を出さない。
- 再活性化による予約成立時の予約完了メール再送は既存の通知機構でそのまま発火するため、本変更では DB / Edge Function / メール送信ロジックの改修は行わない。

## Capabilities

### New Capabilities

（なし。既存ケイパビリティの要件変更のみ）

### Modified Capabilities

- `reservation-history-page`: 履歴のグループ構成に「キャンセル済み」を追加し、キャンセル済予約を過去グループから分離。受付可能な行に再予約導線を持たせる
- `reservation-booking-flow`: 完了画面経由キャンセル後の遷移要件を「受付可能なら再予約導線提示」に更新し、イベント詳細を起点とした予約 Sheet 起動の入口を再予約導線にも開放する

## Impact

- 影響アプリ: `apps/reservation`（会員予約サイト）のみ
- 影響範囲: 履歴画面のグループ分割・行表示、予約完了画面のキャンセル後挙動、イベント詳細画面の予約 Sheet 起動入口
- DB / RLS / Edge Function / メール送信: 改修なし（既存の再活性化 UPDATE と確認メール通知をそのまま流用）
- Non-goals（別 Issue）: キャンセル待ち管理 (#154) 連携 / 通知設定 (#157) からの再予約レコメンド / キャンセル理由の取得・分析
