## Context

- 予約サイトには既に以下が実装されている:
  - イベント詳細 `/events/:id` に `?book=1` を付けると、受付可能なら予約シートを自動で開く（spec `reservation-booking-flow`「予約 Sheet のディープリンク起動 (再予約導線)」）
  - 未ログインで保護ページに来ると `/login?next=<元のパス>` に回し、ログイン・会員登録・本人確認書類提出を経て `next` に戻す（spec `reservation-member-auth`「認証フローにおける `next` クエリの引き継ぎ」）
  - ログイン状態は `localStorage` に保存され、期限なしで自動更新される。Supabase 側の無操作タイムアウトは有料プラン限定のため未設定。admin だけがクライアント側で 3 時間の無操作ログアウトを持つ（#297「Supabase Auth セッション継続時間を 3h に延長」）。予約サイトには無い
- 告知が面倒な原因は、(a) 告知が一覧 URL を貼っている、(b) LINE のリンクはアプリ内ブラウザで開くが、ログイン用メールのリンクは標準ブラウザで開くため、ログイン状態が LINE 側に残らない、の 2 点。
- 告知文はオーナーが `announcements/` の下書きを手で書き換えている。定型部分（挨拶・持ち物など）と、イベントごとに変わる部分（日時・会場・参加費・予約 URL）がはっきり分かれている。
- admin のイベント詳細データ（`event_detail_view`）には、イベント名・回号・日時・会場名・参加費（会場の既定額を引き継いだ値）・定員がそろっている。

## Goals / Non-Goals

**Goals**
- イベント詳細から、テンプレートにイベント情報を差し込んだ告知文をワンタップでコピーできる
- テンプレートは admin 画面で編集できる（LINE 用 1 つ）
- 告知リンク 1 本で「標準ブラウザで開く → 予約シートが開いている」状態にする
- 予約済みの会員がリンクを開いても重複予約に進ませない

**Non-Goals**
- 複数テンプレートの管理・選択
- LINE 共有画面の起動、イベント作成直後の自動表示（#288 の範囲）
- ログイン無しでのイベント詳細閲覧、ログイン方式の変更

## Decisions

### D1. 告知リンクの形: 既存のイベント詳細 + 自動オープン + 外部ブラウザ指定

`<予約サイト>/events/<イベントID>?book=1&openExternalBrowser=1`

- `book=1`: 既存の予約シート自動オープン。受付終了・満席なら開かない判定も既存のまま使える。
- `openExternalBrowser=1`: LINE 公式のリンクパラメータ。LINE アプリ内でタップされたとき、端末の標準ブラウザで開く。LINE 以外では未使用のクエリとして無害。
- 未ログイン時は既存ガードが `next` にクエリごと保持するため、ログイン後に `book=1` 付きで戻り、予約シートが開く。

**検討した代替案**
- 短縮用の新ルート（`/e/<id>` 等）: ルート・ガード・テストが増える。LINE はリンクをプレビュー表示するので長さの不利は小さく、不採用。
- `book=1` 無し: 「予約する」1 タップ分の差。告知から来る人の目的は予約なので自動で開く方を採用。

### D2. ログインの持ち越し: 外部ブラウザへ逃がす（ログイン方式は変えない）

ログイン状態が残る標準ブラウザで開かせれば、2 回目以降はログイン不要になる。マジックリンクも標準ブラウザで開くので、初回ログインから予約確定までブラウザが途中で変わらない。

**検討した代替案**
- 6 桁コード入力でのログイン（アプリ内ブラウザのまま完結）: アプリ内ブラウザの保存領域は消えやすく、毎回ログインに近い状態が残る。認証方式の変更範囲も大きい。効果を見てから判断。

### D3. テンプレートの保存: チャネル単位の 1 行を持つテーブル

新テーブル `announcement_templates` に「チャネル（現状は `line` のみ）→ 本文」を 1 行で持つ。

- 主キーをチャネルにし、チャネルの値は `line` だけを許可する。将来ジモティー用などを足すときは許可値を増やすだけで済む（今回は使わない）。
- 本文は必須で、LINE の 1 メッセージ上限に合わせて 5,000 文字以内。
- 最終更新者・更新日時を持つ（誰がいつ変えたか追えるように）。
- migration で初期テンプレート（現在の LINE 告知下書きを差し込み項目に置き換えたもの）を投入する。初回から告知文コピーが使える。
- RLS: 読み取り・作成・更新は admin のみ（既存 `is_admin()`）。削除ポリシーは作らない（テンプレートを空にする操作は無い）。会員（authenticated の非 admin）・anon からは見えない。
- GRANT: anon は剥奪、authenticated は select / insert / update（RLS で admin に絞る）、service_role は全権（将来の自動投稿用、テンプレート規約どおり）。

**検討した代替案**
- 汎用の設定テーブル（キー / 値）: 他の設定と混ざり、RLS や型が曖昧になる。今回は告知専用にする。
- テンプレートをコードに固定（DB なし）: 翔太郎くんの「管理画面から編集したい」要件を満たさない。
- ブラウザの `localStorage` に保存: 端末ごとにバラバラになり、PC で直したものがスマホに反映されない。

### D4. 差し込み項目: `{日本語名}` 形式

テンプレート内の `{日付}` のような波括弧で囲んだ日本語名を、イベント情報で置き換える。書く人（翔太郎くん）が読んでそのまま分かる表記を優先した。

| 差し込み項目 | 内容 | 値が無いとき |
|---|---|---|
| `{イベント名}` | イベント名 | — |
| `{回号}` | `vol.42` の形 | 空文字 |
| `{日付}` | `11/14(土)`（日本時間） | — |
| `{開始時刻}` / `{終了時刻}` | `18:00`（日本時間） | — |
| `{会場}` | 会場名 | 空文字 |
| `{参加費}` | `1,000円`（0 円は `無料`） | `未定` |
| `{定員}` | `24名` | 空文字 |
| `{予約リンク}` | D1 のリンク | — |

- 表にない `{...}` は置き換えずにそのまま残す（本文中の普通の波括弧を壊さないため）。テンプレート編集画面では「知らない差し込み項目」として注意表示する（保存は妨げない）。
- 日時は端末のタイムゾーンに関係なく日本時間で整形する（海外からの操作でもずれないように）。
- 集合時刻など、今のイベントデータに無い情報は差し込み項目にしない。テンプレートの定型文として書いてもらう。

### D5. 告知文コピーの UI: イベント詳細のヘッダからダイアログ

- イベント詳細ヘッダの「編集」の左に「告知文をコピー」を置く。押すとダイアログが開き、差し込み済みの告知文をプレビューする。
- ダイアログの操作: 「告知文をコピー」（主）/「リンクだけコピー」/「テンプレートを編集」（告知テンプレート画面へ）/ 閉じる。
- いきなりコピーせずプレビューを挟むのは、貼る前に内容（特に日時・参加費）を目で確認できるようにするため。
- コピー成功はトースト。失敗（クリップボード API 不可・拒否）時はエラートーストを出し、プレビュー欄を選択可能な読み取り専用テキストエリアにして全選択する（手動コピーへ退避）。

**検討した代替案**
- ボタン 1 つで即コピー（ダイアログ無し）: 1 タップ少ないが、誤った内容に気づかず貼りやすい。告知は送り直しが目立つため確認を優先。
- ダイアログ内でその場だけ文面を編集: コピー後に LINE 上で直せるので今回は入れない。

### D6. 告知テンプレート画面: ナビに独立項目を追加

- ルート `/announcement-template`、ナビ名「告知テンプレート」。テンプレートは 1 つなので一覧は持たず、編集フォームのみ。
- 構成: 本文テキストエリア（`FormField` でラップ）/ 差し込み項目の一覧（押すとカーソル位置に挿入）/ サンプルのイベント情報で展開したプレビュー / 保存ボタン。
- スマホでは「本文 → 差し込み項目 → プレビュー」の縦積み、PC では本文とプレビューの 2 カラム。
- 入力チェック: 空は保存不可、5,000 文字超は保存不可（残り文字数を表示）。知らない差し込み項目は注意表示のみ。
- 同時編集: admin は実質 1 人のため、後から保存した方が勝つ（更新日時を表示して気づけるようにする）。

**検討した代替案**
- ナビに出さず、告知ダイアログの「テンプレートを編集」からだけ辿る: 画面は増えないが、「どこで直すのか」が分かりにくい。要望の「管理画面から設定・編集」に合わせて独立項目にする。

### D7. 予約サイト URL の取得: admin に設定モジュールを新設（環境変数は任意）

LP の既存実装を踏襲し、admin の `shared/config` に置く。環境変数 `VITE_RESERVATION_URL` が無ければ本番 URL を使う。`render.yaml` は変更しない（本番は既定値で正しいため）。ローカル確認時だけ環境変数でローカル予約サイトに向ける。

### D8. 予約サイト側: 予約済みの会員には予約シートを自動で開かない

現状の自動オープンは「未開催かつ満席でない」だけを見ている。告知リンクは予約済みの会員もタップするため、そのままだと新規予約シートが開き、確定時に重複エラーになる。

- 条件に「本人に有効な予約（予約済み / キャンセル待ち）が無いこと」を加える。キャンセル済みの人は従来どおり開く（再予約導線を維持）。
- 本人の予約状態の取得が終わるまで判定を待つ。取得に失敗した場合は開かない側に倒す。

### D9. 予約サイト側: 着地後に LINE 用パラメータを URL から外す

`openExternalBrowser` は LINE にだけ意味があるため、イベント詳細に着地したら `book` と同様に `router.replace` で外す。`book` が無い場合でも外す。

## 4. DB & セキュリティ

### SQL Migration（概要。具体 SQL は tasks.md）

- `supabase/templates/new_table.sql` を出発点に `announcement_templates` を作成:
  - `channel text primary key check (channel in ('line'))`
  - `body text not null check (char_length(body) between 1 and 5000)`
  - `updated_by uuid references public.members(id) on delete set null`
  - `created_at` / `updated_at`（既存 `set_updated_at()` トリガー）
- RLS 有効化 + ポリシー: select / insert / update を `public.is_admin()` に限定。delete ポリシーは作らない。
- GRANT: anon は `revoke all`、authenticated は select / insert / update、service_role は全権。
- 初期テンプレートを `insert ... on conflict (channel) do nothing` で投入。
- `-- ROLLBACK:` コメントを付ける。

### TypeScript 型

- admin `entities/announcement-template/model/types.ts`: `AnnouncementChannel = "line"` / `AnnouncementTemplate { channel; body; updatedAt; updatedBy }`。

### その他

- 告知リンクにはイベント ID のみが含まれる。イベント ID は LP 経由で既に公開されている値で、個人情報・秘密情報は含まない。
- テンプレート本文は admin しか読めない。会員の個人情報は差し込み項目に含めない。
- 予約サイトの `next` 安全性検証（`safeNextPath`）はクエリが増えても変わらない。
- 本番反映: マージ後、CI の prd migration 適用ジョブが承認待ちになる。承認して適用を見届ける。適用後に `verify_grants.sql` で権限を確認する。

## Risks / Trade-offs

- [オープンチャットで外部ブラウザ指定が効かない] → Apply 中に iPhone / Android の実機で確認。効かなくても「一覧から選ぶ手間」と「告知文作成の手間」の削減は成立する。結果は PR 本文に記録。
- [iPhone の Safari が 7 日間未訪問でログイン状態を消す] → 時々ログインし直しになる。ログイン後は予約シートに直行する。根本対策は効果を見てから別 Issue。
- [テンプレートを誤って壊す（差し込み項目を消す等）] → プレビューで確認できる + 告知文ダイアログでも貼る前に確認できる。初期テンプレートは migration に残るため、内容は参照できる。
- [migration の本番適用漏れ] → マージ後の承認ゲートを ship 手順で見届ける。適用前に admin が先にデプロイされた場合、テンプレート取得が失敗し異常系 2 の表示になる（リンクだけコピーは使える）。
- [admin の開発環境からコピーしても本番 URL] → 意図どおり。ローカル確認時のみ環境変数で差し替える。

## Migration Plan

1. PR マージ → admin / reservation 本番デプロイ + prd migration 適用ジョブが承認待ち
2. 承認して適用 → `verify_grants.sql` で `announcement_templates` の権限を確認
3. admin で告知テンプレート画面を開き、初期テンプレートが表示されることを確認
4. ロールバック: アプリは revert。テーブルは migration の `-- ROLLBACK:` 手順で削除（他テーブルからの参照なし）
