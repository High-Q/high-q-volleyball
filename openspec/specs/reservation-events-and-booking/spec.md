# reservation-events-and-booking Specification

## Purpose

会員サイト (`apps/reservation`) の「探す」体験 — イベント一覧画面とイベント詳細画面の責務を規定する。Epic #170「メンバーが High Q に参加し、繰り返す」のユーザージャーニー前半 (探す) を担い、後続の予約導線 (`reservation-booking-flow` capability) への入口を提供する。MVP1 スコープに合わせて定員・紹介文・写真・キャンセル期限・中止表示等は含まず、扱う情報をイベント名・開催日時・会場 (名 + 集合場所)・参加費の 4 項目に純化する。
## Requirements
### Requirement: イベント一覧画面

会員サイトはログイン後ホームを兼ねるイベント画面を SHALL 提供する。本画面は **「自分の次回予約 (NEXT カード)」を主役とし、その下に他の開催予定を並べる** 二段構成のホームとして機能する MUST。

#### NEXT カード (画面上部)

ログイン会員自身の予約 (`reservations`) のうち、次の条件を満たす **最早の 1 件** を NEXT カードとして描画する SHALL:

- 予約ステータスが「予約済み」(キャンセル済みではない)
- 紐付くイベントの開始時刻が現在時刻より未来

NEXT カードは黒地のヒーロー型レイアウトで、以下を表示する MUST:

- 開催日 (月日 + 曜日 + 開始時刻 + 終了時刻)
- イベント名
- 会場名
- 開催までの残り日数を示すカウントダウン表記
- 表示用予約番号
- 「NEXT」を示す円形バッジ
- 詳細導線 (「詳細を見る →」アフォーダンス)

NEXT カード全体は **押下で当該予約の予約詳細画面に遷移** する MUST。イベント詳細画面ではなく予約詳細画面に向かうのは、NEXT 表示時点でユーザーは予約済みであり、関心が「予約番号 / 同伴者数 / キャンセル動線」に寄るため SHALL。

該当する予約が 0 件の場合、NEXT カードは描画されず、上部の余白を詰めて他のイベントセクションが繰り上がる SHALL。

#### 他のイベント (NEXT の下)

NEXT カードに表示中のイベントを除いた、開催予定 (公開済み・スケジュール済み・開催日が現在以降) のすべてのイベントを開催日昇順で表示する SHALL。

各行に表示する情報:

- 開催日 (月日 + 曜日)
- イベント名
- 開始・終了時刻
- 参加費
- **予約埋まり具合チップ**（「予約埋まり具合の表示」要件に従う）

各行は押下でイベント詳細画面へ SHALL 遷移する（満員行も含めて押下可能。満員時の予約導線 disabled は詳細画面の CTA 側で扱う）。

経験レベルバッジは MVP1 では描画しない SHALL（経験レベル区分は MVP1 スコープオフ）。満員表示と予約埋まり具合チップは「予約埋まり具合の表示」要件に従って描画する MUST。

#### ヘッダ

画面ヘッダには以下を SHALL 配置する:

- 左: サイトロゴ (ブランド和文セリフ書体の「High Q」 + サブのモノスペース文字)。**押下不可** (ホーム画面専用ヘッダのため、ホームへの自己リンクは設けない)
- 右: 円形のユーザーアバター。背景は accent-soft、文字色は accent。表示文字はログイン会員の表示名 (会員視点表示の名前優先ルールに従う) の頭 1 文字。押下でプロフィール画面に遷移する

ホーム画面にはパンくずを描画しない MUST NOT (ルート画面であり、Bottom Tab Bar が一次ナビゲーションを担うため)。

#### 「こんにちは」メッセージ

NEXT カードの直上に、ログイン会員の表示名を含む挨拶 kicker (`— こんにちは、<表示名>さん`) を SHALL 描画する。表示名解決は会員視点表示の名前優先ルール (`reservation-member-auth` capability 参照) に従う。

#### Scenario: 予約あり時の NEXT カード描画
- **WHEN** ログイン会員が未来の予約を 1 件以上持ち、ホームにアクセスする
- **THEN** 最早の 1 件が NEXT カードとして描画され、開催日・曜日・時刻・イベント名・会場名・カウントダウン・予約番号・NEXT バッジが表示される

#### Scenario: 予約 0 件時のホーム
- **WHEN** ログイン会員が未来の予約を 1 件も持たずホームにアクセスする
- **THEN** NEXT カードは描画されず、ヘッダ + 挨拶 + 「他のイベント」セクションのみが上から詰めて表示される

#### Scenario: NEXT カード押下で予約詳細へ遷移
- **WHEN** ユーザーが NEXT カードを押下する
- **THEN** 該当する自分の予約の予約詳細画面 (`reservation-detail-page` capability) へ遷移する

#### Scenario: 他のイベントは NEXT のイベントを除外
- **WHEN** NEXT カードに乗っているイベントが他に開催予定として存在する
- **THEN** 「他のイベント」リストには当該イベントは描画されず、それ以外の upcoming イベントが開催日昇順で並ぶ

#### Scenario: 他のイベントの全件表示
- **WHEN** NEXT を除く upcoming イベントが複数件存在する
- **THEN** truncate されず、全件が開催日昇順で描画される

#### Scenario: 他のイベントが 0 件のとき
- **WHEN** NEXT カードを除き、他に開催予定のイベントが 1 件も存在しない
- **THEN** 「現在他に開催予定のイベントはありません」相当の説明文が表示される (NEXT カードがある場合は NEXT のみが描画される正常状態として扱う)

#### Scenario: 取得エラー時
- **WHEN** 自分の予約またはイベント情報の取得が失敗する
- **THEN** エラーメッセージと再試行操作が表示される

#### Scenario: 読み込み中の状態
- **WHEN** 自分の予約とイベント情報の取得中
- **THEN** 読み込み中であることがユーザーに視覚的に伝わる (NEXT カード代替プレースホルダ + 行プレースホルダ)

#### Scenario: 他のイベント行の押下
- **WHEN** ユーザーが「他のイベント」内の任意行を押下する
- **THEN** イベント詳細画面 (`reservation-events-and-booking` capability の「イベント詳細画面」要件) へ遷移する

#### Scenario: 右上アバターの表示文字
- **WHEN** ホーム画面が描画される
- **THEN** 右上アバターには会員の表示名 (ニックネーム優先) の頭 1 文字が表示される

#### Scenario: 右上アバター押下でプロフィールへ
- **WHEN** ユーザーが右上アバターを押下する
- **THEN** プロフィール画面 (`/profile`) へ遷移する

#### Scenario: 経験レベルバッジが表示されない
- **WHEN** 「他のイベント」リストの任意行を確認する
- **THEN** 経験レベルバッジ（「初心者」等）は描画されない（各行は日付・名前・時刻・参加費・予約埋まり具合チップで構成）

### Requirement: イベント詳細画面

会員サイトはイベント詳細画面を SHALL 提供する。本画面はミニマル構成とし、会員が予約判断に必要な情報を簡潔に提示する MUST。

画面に含む要素:

- 開催日見出し
- イベント名
- 主要情報（開催日時・会場名・**集合場所**・参加費・**予約埋まり具合**）
- 参加費を併記した「予約に進む」ボタン（画面下部に常時可視で配置）

**集合場所**は一覧カードには表示せず、詳細画面でのみ表示する SHALL。これにより詳細画面が一覧カードに対する情報差分を持ち、「タップして見る価値」が成立する。集合場所のデータは `venues` テーブルの `meeting_point` 列をマスタとして保管し、未設定会場は default 値「現地集合」が表示される。

**予約埋まり具合**は facts grid 内に 1 行追加する形で表示し、「予約埋まり具合の表示」要件のテキスト規則に従う MUST。

「予約に進む」ボタンは押下時に予約確認 **Bottom Sheet** を開く MUST。独立した予約確認ルートには遷移しない MUST NOT (詳細画面 URL を維持し、Sheet 内で同伴者数 / 連絡事項 / 合計金額 / 確定 CTA を完結させる)。本ボタンは予約導線 (`reservation-booking-flow` capability) の入口として機能する。

満員時（capacity あり、かつ 予約埋まり具合 >= capacity）は「予約に進む」ボタンを disabled に切り替え、ラベルを「予約締切」と表示する SHALL。capacity NULL の場合は満員概念が成立しないため通常挙動を維持する MUST。

紹介文・写真・キャンセルポリシー欄・会場住所そのものは本画面に **含まない** MUST（MVP1 スコープアウト + UX 観点での廃止）。

#### Scenario: 詳細画面の基本表示
- **WHEN** ログイン済み会員が任意イベントの詳細画面にアクセス
- **THEN** 開催日・イベント名・主要情報（開催日時・会場名・集合場所・参加費・予約埋まり具合）・「予約に進む」ボタンが描画される

#### Scenario: 集合場所の表示
- **WHEN** 詳細画面に到達
- **THEN** 会場名と集合場所が両方表示される（一覧では会場名のみだったが、詳細では集合場所も加わる）

#### Scenario: 集合場所が未設定の会場
- **WHEN** `venues.meeting_point` が default 値「現地集合」のまま運用されている会場の詳細を表示
- **THEN** 集合場所欄に「現地集合」が表示される

#### Scenario: 存在しないイベント ID
- **WHEN** 存在しないイベント ID で詳細画面にアクセス
- **THEN** 該当イベントが見つからない旨の表示と、イベント一覧へ戻る導線が提示される

#### Scenario: 「予約に進む」ボタンの押下
- **WHEN** ユーザーが「予約に進む」ボタンを押下する
- **THEN** 予約確認 Bottom Sheet が画面下部から立ち上がる（独立ルートには遷移せず、URL は詳細画面のまま。「準備中」案内表示も描画されない）

#### Scenario: 満員時の CTA disabled
- **WHEN** capacity あり・予約埋まり具合 >= capacity の状態で詳細画面に到達
- **THEN** 「予約に進む」ボタンは disabled 状態となり、ラベルは「予約締切」と表示される。押下しても Bottom Sheet は開かない

#### Scenario: 紹介文・写真・キャンセルポリシー・会場住所の非表示
- **WHEN** 詳細画面の DOM を確認
- **THEN** 紹介文セクション・写真領域・キャンセルポリシー欄・会場住所欄のいずれも存在しない

### Requirement: ログイン後ホームのイベント一覧化

会員サイトの会員ログイン後の到達先はホーム画面 (NEXT カード + 他のイベント) である MUST。従来の「準備中」プレースホルダ画面は SHALL 廃止された状態を維持する。

ホーム URL は引き続き有効とし、アクセス時にホーム画面へ自動的に到達する状態を保つ MUST。これにより既存ユーザーのブックマークが壊れない。

#### Scenario: ログイン後ホームへのアクセス
- **WHEN** プロフィール完成済み会員がホーム URL にアクセス
- **THEN** 認証ガード通過後、ホーム画面 (NEXT カード + 他のイベント) に到達する

#### Scenario: 「準備中」プレースホルダの廃止
- **WHEN** 会員サイトの画面群を確認する
- **THEN** 「準備中」プレースホルダ画面は存在しない

### Requirement: パンくずナビゲーション

会員サイトの各画面はパンくずナビゲーションを統一ウィジェット経由で SHALL 表示する。各画面で独自の `<nav>` 実装を行うことを禁止 MUST。

ただしホーム画面 (`/events`) はルート画面でありパンくずを描画しない MUST NOT。Bottom Tab Bar が一次ナビゲーションを担うため、ルート画面に対するパンくずは情報過多となる。

パンくず構造:

- ホーム画面: パンくずなし
- イベント詳細画面: `マイページ > イベント > [イベント名]`

第 1 セグメント **「マイページ」** はホーム画面への戻り導線を SHALL 提供する。これにより、各画面から上位画面への戻り経路が常に存在し、双方向性ルールが満たされる MUST。

#### Scenario: ホーム画面のパンくず非表示
- **WHEN** ホーム画面にアクセス
- **THEN** パンくずナビゲーションは描画されない

#### Scenario: 詳細画面のパンくず
- **WHEN** イベント詳細画面にアクセス
- **THEN** 「マイページ > イベント > [当該イベント名]」のパンくずが表示される

#### Scenario: マイページリンクの動作
- **WHEN** パンくずの「マイページ」を押下
- **THEN** ホーム画面に到達する

#### Scenario: 独自実装の禁止
- **WHEN** 会員サイトの画面・ウィジェット内でパンくず用 `<nav>` の独自記述を検索
- **THEN** 該当箇所はパンくず専用ウィジェット以外には存在しない

### Requirement: 4 状態 UI の網羅

会員サイトのホーム・イベント詳細の各画面は、以下 4 状態の UI を SHALL 実装する。

- 読み込み中（データ取得中）
- 該当なし（ホームで「自分の予約 0 件 + 他のイベントも 0 件」 / 詳細で対象が見つからない）
- エラー（ネットワーク・権限エラー等）
- 正常表示

エラー状態では再試行操作を SHALL 提示する。該当なし状態では文脈に応じた説明文と次のアクション（一覧へ戻る等）を SHALL 提示する。

予約埋まり具合チップ / 詳細 facts 行については、上記 4 状態と独立した個別の挙動を SHALL 持つ:

- **取得中**: チップ位置に shimmer プレースホルダを描画。主データ（イベント名 / 時刻 / 参加費）の描画は阻害しない MUST
- **取得 0 名**: 「0 名 予約中」と素直に表示する MUST。煽り / 招待文言（「一番乗りになろう」等）は表示 SHALL NOT
- **取得失敗**: 主データの描画は継続し、チップ位置のみ控えめな `—` を表示する MUST。チップ個別の retry ボタンは設けない MUST NOT（一覧 / 詳細の既存 retry 経路に集約）
- **取得成功**: 「予約埋まり具合の表示」要件の文言に従って描画する

ホーム画面の「正常表示」は以下のいずれも含む:

- NEXT カードあり + 他のイベントあり
- NEXT カードあり + 他のイベントなし (NEXT のみが描画される)
- NEXT カードなし + 他のイベントあり (他のイベントのみが描画される)

#### Scenario: ホームの読み込み中
- **WHEN** ホーム画面の初回読み込み中
- **THEN** 読み込み中であることがユーザーに視覚的に伝わる

#### Scenario: ホームの該当なし
- **WHEN** 自分の予約 0 件かつ他の開催予定イベントも 0 件
- **THEN** 「現在開催予定のイベントはありません」相当の説明文と再読込操作が表示される

#### Scenario: 詳細のエラー
- **WHEN** 詳細画面のデータ取得が失敗
- **THEN** エラーメッセージと再試行操作が表示される

#### Scenario: 詳細の該当なし
- **WHEN** 存在しない / 公開対象外のイベント ID で詳細画面にアクセス
- **THEN** 「イベントが見つかりません」相当の説明文と、ホームへ戻る導線が表示される

#### Scenario: 予約埋まり具合チップの取得中
- **WHEN** 一覧画面で予約埋まり具合の集計値を取得中
- **THEN** 各行のチップ位置に shimmer プレースホルダが描画され、イベント名 / 時刻 / 参加費は通常通り表示される

#### Scenario: 予約埋まり具合 0 名
- **WHEN** イベントの予約埋まり具合の集計値が 0
- **THEN** チップは「0 名 予約中」と表示され、煽り / 招待文言は付加されない

#### Scenario: 予約埋まり具合の取得失敗
- **WHEN** 一覧 / 詳細でイベント本体の取得は成功し、予約埋まり具合の集計値の取得のみ失敗
- **THEN** チップ / facts 行は `—` で fallback 表示され、その他の情報は通常通り描画される。チップ自体に retry ボタンは描画されない

### Requirement: デザイントークンの徹底使用

会員サイトのイベント一覧・詳細画面のスタイリングは HQ デザイントークン経由（プロジェクトの Tailwind 設定 utility または HQ ブランドの CSS 変数経由）でのみ SHALL 行う。生の色コード・ピクセル値・rem 値の直書きを禁止 MUST する。

書体は見出しはブランド和文セリフ書体、本文はブランド和文ゴシック書体、数値はモノスペース書体を SHALL 使用する。

#### Scenario: マジックナンバー検出
- **WHEN** 該当画面のテンプレート / スタイルから生の色コード・ピクセル値・rem 値の直書きを検索
- **THEN** ヒット 0 件（すべてトークン経由）

### Requirement: アクセシビリティ AA

会員サイトのイベント一覧・詳細画面は WCAG 2.1 AA 相当のアクセシビリティ要件を SHALL 満たす:

- テキストと背景のコントラスト比が AA 基準を満たす
- イベントカード・ボタン・パンくずリンクがキーボード操作で到達・実行できる
- スクリーンリーダーがイベント情報を構造化された形で読み上げられる（適切な見出しレベル・ランドマーク・aria 属性）

#### Scenario: キーボード操作
- **WHEN** ポインタを使わずキーボードのみで一覧画面を操作する
- **THEN** すべてのイベントカード・パンくず・アカウントメニューが Tab で到達でき、Enter で実行できる

#### Scenario: スクリーンリーダー読み上げ
- **WHEN** スクリーンリーダーで詳細画面を読み上げる
- **THEN** 見出し階層に従ってイベント情報が順序立てて読み上げられる

### Requirement: 主要シナリオの自動テストカバレッジ

会員サイトのホーム / 詳細の主要シナリオは、component test（Vitest + @vue/test-utils）レベルで SHALL 自動検証される。`apps/reservation` には E2E（Playwright）環境が現状存在しないため、本 capability では component test での代替を許容する MUST。E2E 環境一式のセットアップと再テストは別 Issue (#201) で扱う。

検証対象シナリオ:

- ホームの NEXT カードに、自分の最早の予約済みイベントが描画される
- 自分の未来予約が 0 件のとき、NEXT カードが描画されない
- NEXT カードを押下すると `/reservations/:reservationId` ルートへ navigate される
- 「他のイベント」リストから NEXT 対象のイベントが除外される
- 「他のイベント」行を押下するとイベント詳細ルートへ navigate される
- 「他のイベント」行に経験レベルバッジが描画されない
- 「他のイベント」行に予約埋まり具合チップが描画される（capacity NULL / capacity あり / 満員 の 3 ケース）
- 詳細画面の facts grid に予約埋まり具合行が描画される（capacity NULL / capacity あり / 満員 の 3 ケース）
- 満員時に詳細画面の「予約に進む」CTA が disabled になり、ラベルが「予約締切」に切り替わる
- 予約埋まり具合の集計値取得失敗時、チップ / facts 行が `—` で fallback 表示される
- 右上アバターに会員の表示名の頭 1 文字が描画され、押下で `/profile` へ navigate される
- 認証ガードがホームルートに対して機能する

#### Scenario: component test の整備
- **WHEN** `pnpm --filter @high-q/reservation test` を実行する
- **THEN** 上記シナリオに対応する component / unit / router-guard テストが pass する

#### Scenario: E2E 環境セットアップは別 Issue
- **WHEN** 後続 Issue #201 の完了時点

### Requirement: venues.meeting_point マスタ保管

詳細画面で表示する集合場所は、`venues` テーブルの `meeting_point` 列をマスタとして SHALL 保管する。アプリ層で会場名から集合場所を判定するハードコード分岐は禁止 MUST する。

`meeting_point` は `text NOT NULL default '現地集合'`。新規会場 INSERT 時に明示指定がなければ default が適用される。会場ごとに異なる集合場所を持つ場合は admin 側 (#151 会場マスタ CRUD) の編集 UI で運用するが、本 capability の責務範囲ではない。

#### Scenario: 集合場所がマスタから読まれる
- **WHEN** 詳細画面が任意イベントを表示する
- **THEN** 表示される集合場所は `venues.meeting_point` 列の値（default '現地集合' を含む）と一致する

#### Scenario: アプリ層ハードコード判定の禁止
- **WHEN** 会員サイトの実装ファイルを `venue.name === '<具体名>'` のような会場名固有の文字列比較で grep
- **THEN** 集合場所判定のための条件分岐は存在しない（全て DB の `meeting_point` 列を参照）

### Requirement: 予約埋まり具合の表示

会員サイトのイベント一覧（「他のイベント」セクションの各行）、イベント詳細画面、および **NEXT カード** は、当該イベントの予約埋まり具合を SHALL 表示する。表示は `capacity` の有無で動的に切り替わり、admin と同じ集計母集団（本人 + 同伴の人数ベース、`status IN ('reserved', 'attended')` をカウント、`cancelled` は除外）を共有する MUST。

表示テキストは以下の規則に従う MUST:

| capacity 状態 | 一覧チップ | 詳細 facts 行 | 詳細「予約に進む」CTA | NEXT カード strip |
|---|---|---|---|---|
| `capacity = NULL` | 「N 名 予約中」 | ラベル「予約状況」/ 値「N 名 予約中」 | 通常表示 | 「N 名 予約中」 + `UNCAPPED` モノラベル |
| `capacity` あり、`booked < capacity` | 「あと N 名 募集」（N = `capacity - booked`） | ラベル「残り」/ 値「あと N 名 募集」 | 通常表示 | 「あと N 名 募集」 + 黒地用 progress bar |
| 満員（`booked >= capacity`） | 「満員」 | ラベル「予約状況」/ 値「満員」 | disabled + ラベル「予約締切」 | 「満員」 + 黒地用 progress bar |

「席」という語は使用 SHALL NOT する（物理席との混同回避）。一覧チップ / 詳細 facts 行ともにプログレスバーは描画 MUST NOT する（当面 `capacity = NULL` 一辺倒のため意味を持たない。`capacity` 入力 UI 復活時に追加検討）。

NEXT カードでは availability strip を黒地ヒーローカードの下端に `border-top` 区切りで配置する MUST。strip は左端に色付き dot indicator、中央に文言、右端に `capacity` あり時は黒地用 progress bar、`capacity = NULL` 時は `UNCAPPED` モノスペースラベルを配置する SHALL。

#### Scenario: capacity NULL のイベント一覧チップ
- **WHEN** capacity NULL のイベントで予約埋まり具合の集計値が 11 名（本人 + 同伴の人数ベース）
- **THEN** 該当行のチップに「11 名 予約中」と表示される

#### Scenario: capacity あり、残席ありのイベント一覧チップ
- **WHEN** capacity = 18、予約埋まり具合の集計値が 11 名
- **THEN** 該当行のチップに「あと 7 名 募集」と表示される

#### Scenario: 満員のイベント一覧チップ
- **WHEN** capacity = 18、予約埋まり具合の集計値が 18 名以上
- **THEN** 該当行のチップに「満員」と表示される

#### Scenario: 詳細画面 facts grid に予約埋まり具合行が追加される
- **WHEN** イベント詳細画面が描画される
- **THEN** Date / Time / Venue / Fee に加えて、予約埋まり具合の行が facts grid に表示される

#### Scenario: 満員時の詳細 CTA disabled
- **WHEN** capacity = 18、予約埋まり具合の集計値が 18 名以上の状態で詳細画面に到達
- **THEN** 「予約に進む」CTA は disabled となり、ラベルは「予約締切」と表示される

#### Scenario: NEXT カードに予約埋まり具合 strip が描画される (capacity NULL)
- **WHEN** capacity NULL のイベントを NEXT カードとして表示し、予約埋まり具合の集計値が 9 名
- **THEN** NEXT カード下端の strip に「9 名 予約中」と表示され、右端に `UNCAPPED` モノラベルが描画される

#### Scenario: NEXT カードに予約埋まり具合 strip が描画される (capacity あり残あり)
- **WHEN** capacity = 18 のイベントを NEXT カードとして表示し、予約埋まり具合の集計値が 14 名
- **THEN** NEXT カード下端の strip に「あと 4 名 募集」と表示され、右端に黒地用 progress bar が描画される

#### Scenario: NEXT カードに予約埋まり具合 strip が描画される (満員)
- **WHEN** capacity = 18 のイベントを NEXT カードとして表示し、予約埋まり具合の集計値が 18 名以上
- **THEN** NEXT カード下端の strip に「満員」と表示され、右端に黒地用 progress bar (full) が描画される

#### Scenario: 「席」表記の不採用
- **WHEN** 会員サイトの DOM 全体を `残席` / `空席` 等の「席」を含む表記で検索
- **THEN** いずれの画面にも該当表記は存在しない
