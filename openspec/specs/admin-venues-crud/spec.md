## Requirements
### Requirement: 会場マスタのマスター・ディテール画面

システムは admin の `/venues` を、左ペイン=会場リスト（固定幅）/ 右ペイン=詳細・編集フォームの 2 ペイン マスター・ディテール画面として提供 MUST する（プロトタイプ「会場マスタ B案」準拠）。一覧・新規作成・編集・削除はこの単一画面内で完結し、作成・編集用の別ルートは持たない SHALL。色は HQ デザイントークン経由で表現し、生 hex を使わない MUST。

#### Scenario: 2 ペインの表示
- **WHEN** admin が `/venues` を開く
- **THEN** 左に会場リスト、右に先頭会場の詳細フォームが 1 枚のカード内に表示される

#### Scenario: 読み込みの状態表示
- **WHEN** 一覧取得が Loading / 取得失敗 / 会場 0 件 / 取得成功 のいずれかの状態にある
- **THEN** それぞれ Loading 表示 / Error 表示（理由＋再試行）/「会場が登録されていません」/ リスト＋詳細 を表示する

### Requirement: 会場リスト（左ペイン）と検索

システムは左ペインに会場名昇順のリストを表示 MUST する。各項目は会場名と、右側にメイン会場なら「メイン」バッジ・通常は料金（固定額は `¥金額` / 都度設定は「都度」）を示す SHALL。選択中の項目は左ボーダーをアクセント色＋淡い背景で強調する MUST。上部の検索入力で会場名・住所の部分一致フィルタを提供し、メタ行に件数（絞込 / 全件）を表示する MUST。

#### Scenario: 会場を選択して詳細をロード
- **WHEN** 左リストの会場をクリックする
- **THEN** 右ペインに当該会場の内容がドラフトとしてロードされ、項目が選択状態（アクセント強調）になる

#### Scenario: 会場名・住所で絞り込む
- **WHEN** 検索欄に文字列を入力する
- **THEN** 会場名または住所に当該文字列を含む項目のみ表示され、メタ行の絞込件数が更新される

#### Scenario: 該当なし
- **WHEN** 検索条件に一致する会場が無い
- **THEN** リスト領域に「該当する会場がありません」を表示する

### Requirement: 詳細フォームの項目と編集

システムは右ペインに次の編集項目を提供 MUST する: 会場名（必須）/ 住所（郵便番号は住所に統合・独立列なし）/ 料金タイプ（固定額・都度設定のセグメント）/ 標準参加費（固定額のとき有効・都度設定のとき無効表示）/ アクセスメモ（全文表示・改行可・省略しない）/ 地図・位置情報（`map_url` に保存・値があればプレビュー、空なら「位置情報が未設定です」）/ メイン会場トグル。見出し横にメインバッジ、補助テキストに最終更新・ID を表示する SHALL。集合場所（`meeting_point`）の編集欄は本画面には持たず、更新時に送信しないことで既存値を保持する MUST。

#### Scenario: 料金タイプの切替で金額欄を有効・無効化
- **WHEN** 料金タイプを「都度設定」にする
- **THEN** 標準参加費の金額入力が無効（淡色）になり、保存時 `default_fee` は NULL になる

#### Scenario: 固定額の保存
- **WHEN** 料金タイプ「固定額」で金額を入力して保存する
- **THEN** `default_fee` に当該金額が保存される

#### Scenario: アクセスメモの全文表示
- **WHEN** 複数行のアクセスメモを持つ会場を表示する
- **THEN** 省略されず全文・改行が表示・編集できる

### Requirement: ドラフト編集と未保存変更（dirty）ガード

システムは編集をドラフト状態で保持 MUST する。未保存変更がある（dirty）状態で別会場へ移動・新規追加しようとした場合は確認ダイアログを表示し、破棄を選んだときのみ移動する SHALL。フッターは 保存 / キャンセル（dirty 時のみ有効）/「この会場を削除」（右寄せ）を持ち、dirty 時は「未保存の変更があります」を表示する MUST。

#### Scenario: dirty 中の会場移動
- **WHEN** 編集中（dirty）に別会場を選択する
- **THEN** 確認ダイアログが出て、破棄に同意したときのみ移動する

#### Scenario: キャンセルで変更を破棄
- **WHEN** dirty 状態でキャンセルする
- **THEN** ドラフトが選択中会場の保存値に戻り、dirty が解消される

### Requirement: 保存とバリデーション

システムは保存時に会場名必須・固定額なら金額必須（0 以上の整数）を検証 MUST する。検証エラーは該当フィールドに表示し、保存は行わない SHALL。保存は `venues` への INSERT（新規）または UPDATE（既存）で行い、RLS（`is_admin()`）に従う。成功時はトーストを表示し、一覧と最終更新日を最新化する MUST。会場名重複（UNIQUE 違反）は「同名の会場が既に存在します」相当のメッセージで提示する SHALL。

#### Scenario: 会場名未入力の保存
- **WHEN** 会場名を空のまま保存しようとする
- **THEN** 会場名欄に検証メッセージが表示され、保存は行われない

#### Scenario: 保存成功
- **WHEN** 妥当な内容で保存する
- **THEN** 会場が保存され、成功トーストが表示され、一覧と最終更新日が更新される

#### Scenario: 会場名重複
- **WHEN** 既存と同名の会場名で保存する
- **THEN** 「同名の会場が既に存在します」相当のメッセージが表示される

### Requirement: 新規会場の追加

システムはヘッダーおよびリスト下部の「新しい会場」操作で、空の会場ドラフトを作成して選択状態にする MUST する。新規ドラフトは保存するまで DB に永続化しない SHALL。新規ドラフトの削除（破棄）は DB を変更しない MUST。

#### Scenario: 新規会場を追加
- **WHEN**「＋ 新しい会場」を押す
- **THEN** 空の会場ドラフトが選択状態になり、フォームに入力できる（保存するまで未永続）

### Requirement: メイン会場フラグの一意性維持

システムはメイン会場（`is_primary = true`）を最大 1 件に保つ MUST する。会場を `is_primary = true` で保存する場合、既存のメイン会場を先に `is_primary = false` へ更新してから対象を `true` にする SHALL（同時に 2 件が true にならない順序で適用し、`venues_single_primary_idx` partial unique 違反を回避する）。

#### Scenario: 別会場をメインに切り替える
- **WHEN** 既にメイン会場 A が存在する状態で、会場 B を「メインにする」で保存する
- **THEN** 会場 A の `is_primary` が自動的に false になり、会場 B のみが `is_primary = true` になる

### Requirement: 会場の削除と参照中ガード

システムは詳細フッターから会場の削除操作を提供 MUST する。削除は確認後に `venues` を DELETE し、RLS（`is_admin()`）に従う SHALL。`events.venue_id` は `ON DELETE RESTRICT` のため、イベントが参照中の会場は DB が削除を拒否する。システムはこの参照制約違反（外部キー違反 `23503`）を捕捉し `VENUE_IN_USE` として「使用中のため削除できません」相当の理由を提示 MUST する（汎用エラー文言にしない）。メイン会場を削除した場合はメイン不在を許容する（自動昇格しない）SHALL。

#### Scenario: 未参照の会場を削除する
- **WHEN** どのイベントからも参照されていない会場を削除確認する
- **THEN** 当該会場が DELETE され、一覧から消え成功トーストが表示される

#### Scenario: 参照中の会場を削除しようとする
- **WHEN** イベントが参照している会場を削除しようとする
- **THEN** DB が ON DELETE RESTRICT で拒否し、`VENUE_IN_USE` として「使用中のため削除できません」と理由が表示され、会場は残る

### Requirement: 会場画面への遷移とアクセス制御

システムは `/venues` を admin auth guard 配下に配置 MUST する。未認証・非 admin ユーザーは既存 guard により会場画面へ到達しない SHALL。会場を含む各セクション（ダッシュボード / イベント / 会員 / 本人確認書類 / 会場）への双方向対称の導線は、`admin-responsive-shell` capability のサイドバー / ドロワーが MUST 提供する。会場画面は自前のグローバルナビ行を持たず、ページ header はパンくず + タイトルのみに縮約する SHALL。

#### Scenario: 非 admin は会場画面に到達しない
- **WHEN** 非 admin ユーザーが `/venues` にアクセスする
- **THEN** 既存の admin auth guard によりログイン等へリダイレクトされ、会場画面は表示されない

#### Scenario: シェルから会場画面へ
- **WHEN** admin がシェルのナビ（サイドバー or ドロワー）の「会場」を押す
- **THEN** `/venues` へ遷移し、同じシェルのナビから他セクションへ戻れる

### Requirement: 会場マスター・ディテールのモバイル表示

`/venues` の「左リスト + 右フォーム」master-detail は、デスクトップ（≥ `md`）で横並びを維持する。**モバイル（< `md`）では MUST 横並びをやめ、会場リスト表示と詳細フォーム表示をビュー切替で出し分ける**（リストで会場を選択するとフォームビューへ遷移し、フォームからリストへ戻れる導線を持つ）。詳細フォームは MUST 1 カラムで縦積みになり、行内グリッド（メイン会場フラグ等を含む各項目）も縦積みになる。横スクロールは発生させない。

#### Scenario: モバイルでビュー切替になる
- **WHEN** 画面幅 375px で `/venues` を開く
- **THEN** 左右横並びではなく会場リストが表示され、会場を選択すると詳細フォームビューへ切り替わり、フォームからリストへ戻れる

#### Scenario: モバイルでフォームが 1 カラム縦積みになる
- **WHEN** 画面幅 375px で会場の詳細フォームを表示する
- **THEN** フォーム項目が 1 カラムで縦積みに配置され、横スクロールは発生しない
